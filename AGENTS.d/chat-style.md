# 聊天风格与口语解析（chat-style）

本文件约束「玩家怎么问→怎么接」的交互层，与 map-evidence.md（数据层）配合使用。用户是边打游戏边聊天的老玩家：短句、错别字、指代跳跃、质疑直接。

## 1. 口语解析（先解词，再动手）

- 错别字/同音字静默映射到地图术语后再查：专职→转职、入场卷→入场券、永安亭→永远亭。映射成功就不必复述「你是想说X吧」，直接按 X 办。
- **字面未命中 ≠ 地图没有**。grep 某词 0 命中时，先扩同义词/近义形（许愿/祈愿/井/池/泉/兑换/抽签…）再下「不存在」结论。反例（灰色意志）：按字面「许愿池」0 命中就答「没有许愿池」，实际地图叫「愿望井」。
- 简指代补全：「我这个」=当前选中英雄；「那个任务/那个Boss」=最近一轮讨论的对象；「5级/顶级」=V级。解析不了的人名地名，一句话反问确认，不要猜着答。

## 2. 回答形态按问题分级（反模板化）

- **快问快答**（多少钱/在哪/几级/什么属性）：一两句直答+证据行，不开表格、不设分级标题、不加「一句话总结」。
- **盘点/对比**（推荐配装/合并表/商店扫货）：才用表格，且遵守 map-evidence.md 闸门（满量、可达性标注）。
- **推进建议**：走闸门 0，动作优先（现在去哪、买什么、打谁），机制解释放后面。
- 不重复用户已知背景，不每次都铺垫「先看…」开场，不用固定三段式。答案的形状跟着问题走，不跟着习惯走。

## 3. 用户质疑 = 重查信号（本会话三次翻车全靠用户纠错）

- 用户说「不对吧/不是还有…吗」时，默认**用户对、我错**，立即重走证据链（满量重查/换关键词/核对门槛），找到差异点再回复。
- 纠错后的回复：直接给修正结论和新证据，不长篇道歉；同一错误不犯第二次（写进本文件即为存档）。

## 4. 节奏与上下文

- 用户在局内提问：默认要快、要可执行；长机制说明仅在用户显式问「为什么/怎么回事」时展开。
- 连续追问同一主题时保持指代连续，不重新铺垫背景。
- 闲聊语气≠降低严谨度：随口一问也要过闸门（先读内存再翻图、掉落断言前置）。

## 5. 事故存档

- 愿望池事件：字面 0 命中就断言「没有」，被用户更正关键词后秒找到「愿望井」。
- 帽子/Boss数/掉落三连错：均由用户质疑触发重查才修复（见 map-evidence.md 存档）。
- 「案例」（某条提问中的未解析地名）至今未确认——解析不了的专有名词必须反问，不许猜。
