## 本轮地图查询增量

修改前 `pack_query_object_details.render_object_record` 只输出选中对象自己的字段。
`uabi` / `uhab` 虽可见，却不会展开引用的技能；已有 `item_ability_index` 只消费物品携带技能。
因此用户查一个英雄时，需要自行抄出每个技能码，再逐个查看冷却与距离。

现在 `units` / `heroes` 保留自己的原字段，并展开 `uabi`（默认技能）与 `uhab`（可学习英雄技能）
里可以确认的四码，读取同一知识包、同一技能类别的全部字段。关键词与 Boolean 表达式也能命中
这些关联技能的名称、键、标签、值、来源与额外证据。一个 `--limit` 单位仍包含其完整关联技能，
不会按技能数或输出行数再截断。全局分类搜索通过同一个对象记录得到相同联查语义。

`skills` 及联查技能共用逐级静态参数摘要：

| 参数 | 明确字段身份 |
|---|---|
| 冷却、魔法消耗 | `acdn`、`amcs` |
| 施法距离、作用范围 | `aran`、`aare` |
| 持续时间、英雄持续时间、施法时间 | `adur`、`ahdu`、`acas` |
| 普通、关闭、学习热键 | `ahky`、`auhk`、`arhk` |
| 单位攻击 1 / 2 | 各自的基础伤害、骰子数、骰子面数、间隔、射程与攻击类型字段 |
| 单位护甲、移动和视野 | `udef`、`udty`、`umvs`、`usid`、`usin` |

可直接使用原有入口，例如 `pack-query <包> heroes`、`pack-query <包> units "守卫 && 冷却"`、
`pack-query <包> skills <技能码>`、`pack-query <包> search "单位:寒霜术"`。
GUI 继续使用现有包查询模式，结果和导出由同一 `execute_pack_query` 链路提供。
当地图将英雄保存在“单位”主类别时，使用 `units` 查询；`heroes` 保留原有独立类别合同及改道提示，
不凭显示名或四码拼写猜测身份。本轮真实地图与真实 Tk 窗口验收的范围见本文末尾。

实现文件：

- [pack_query_combat_evidence.py](../../gametool/pack_query_combat_evidence.py)：类型化参数证据与静态摘要。
- [pack_query_unit_abilities.py](../../gametool/pack_query_unit_abilities.py)：单位/英雄技能链接、完整联查与共享搜索字段。
- [pack_query_object_details.py](../../gametool/pack_query_object_details.py)：现有记录加载、搜索及渲染接入。
- [test_pack_query_combat_evidence.py](../../tests/test_pack_query_combat_evidence.py)：本轮行为回归。

查询约束随代码实现：

- 字段表一次读取，各类别按同一索引建立；不同类别同码不会混入技能字段。
- 每个技能的搜索字段只准备一次，多个链接/多个角色不会重复附加同一技能的完整字段。
- 原链接字段和来源保留。默认技能与可学习技能分开；有冲突的多个声明保留各自引用，不称为同时生效。
- 显式空、未知或已覆盖的自定义链接阻止退回继承链接；已覆盖字段仍在原字段段显示。
- 复用 `object_codes.field_object_codes`，保留四字节 Latin-1、大小写、标点、空白及名称后缀；歧义不猜码。
- 参数按实际字段中存在的等级与数据列分开保留，不从 `alev` 分配等级，不将数据列当等级。
- 自定义参数优先于同身份的记录继承值；空值、冲突、未确认状态和非法数字不选一个赢家，也不换取继承值。
- 原值、数值拼写、来源、扩展证据和完整原字段保留；未知 `Data*` 不按标签猜作冷却或范围。
- 只列静态参数，不计算实战 DPS、当前冷却、已学等级、实际持有或插件运行效果。

## 与 War3Tools 的公共接口衔接

War3Tools 配置检查已接入 CLI 与 GUI；对地图查询的增量落在以上共享查询模块，
不把配置文件读取本身重复算作地图内容查询。以下纯数据接口保留明确来源边界：

| 接口 | 适合衔接的内容 | 必须保留的边界 |
|---|---|---|
| `combat_parameters(category, fields, complete=...)` | 从明确地图字段整理冷却、范围、热键与攻防参数；返回 `CombatParameter` | 输入必须已经分类与带来源；不能传插件默认表来冒充地图数据 |
| `render_combat_parameters(...)` | `skills`、单位技能详情、离线参数说明共用呈现 | 每级、每数据列、冲突和原值并存；不生成运行时倒计时或范围圈事实 |
| `unit_ability_evidence(...)` | 单位默认技能/可学习技能的完整只读关联 | 只用明示四码和地图技能字段；不把配置槽位、按钮顺序或名字相似性猜成技能身份 |
| `ReferenceSource` / `ReferenceValue` / `ReferenceRecord` | 未来把外部配置/默认值作为独立来源对照项展示 | 保留样本/文件哈希、配置键、版本未知、数据角色；不得覆盖地图值或宣称运行兼容 |
| `search_reference_catalog` / 现有对象字段 Boolean 搜索 | 独立来源检索或已绑定地图字段的完整查询 | 外部格式仍须专用适配；当前参考目录不自动认识任意 War3Tools 文件 |

`hotkey_config.canonical_hotkey` 与 `inspect_hotkey_config` 明确依据 Hotkeys 2.0.0 的静态 JSON 合同，
包括其键名语法与 42 槽兼容投影；它们不是任意整数 VK/INI 文件的通用解析器。
War3Tools 的原键名、重复项、整数表示、注释和未知配置应留在其专用数据层，再按已证角色建立独立对照。
`gameconfig.py` 的 `.wgc` 对局参数也不应与该配置混用。
