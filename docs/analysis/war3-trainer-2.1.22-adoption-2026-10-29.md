## 已确认的来源问题

1. 火龙界面保存 `prefix`、`features`、`resource_amount`，实际 HKE 生成主要消费
   `artifact_codes`，命令前缀仍是固定 `-`。保存的选项不能当作已对输出生效。
2. 保护技能的包装只拦截部分添加/删除调用；旧火龙函数中仍有直接设置技能等级和永久状态的路径。
   因此不能声称受保护技能在整个生成脚本中完全不受影响。
3. pjass 的 `//#` 注解可以开启 `+nosyntaxerror` / `+nosemanticerror`，将错误计入
   `ignorederrors`；即使打印 `N errors ignored`，主函数也可能返回 0。
   Trainer 仅由退出码 0 设置 `syntax_and_types=True`，证据不足。
4. 前端在开始作业请求尚未拿到新 job ID 时允许停止，停止可能查询空/旧作业并返回，
   后续新作业仍可开始；需要完整处理请求中状态才能宣称停止生效。
5. 旧存档和内存代码 RPC 的 dict/list 形状问题、初始化按钮误路由仍存在。
   本版页面或版本号变化没有修复这些既有链路。
6. 当前原生桥仍缺 `talent_probe`、`equipment_probe`、`cooldown_probe` 三项诊断导出。
   Python 操作注册表存在，不证明发行 DLL 具备该能力。
7. MPQ 目录保全不等于任意加密图都能生成副本。实际 HKE 变更发布先逐成员读取并计算指纹，
   需要修复归档头时还会完整读取成员快照，之后再读回验证。缺少真名且无法恢复 key 的加密成员
   会条件性阻断这些步骤；无改动的提前返回分支与正常头路径另有明确控制流，不混为必然失败。

上列为静态调用链与字节证据结论；本轮没有执行 Trainer 或在当前游戏中重现其运行效果。
曾怀疑的校验正则转义问题经常量原字节复核已排除，没有作为缺陷保留。
