# 七个 Warcraft 工具的复核与 GameXRay 0.8.0 实施对照

日期：2026-10-28。采用前源码基线：`1aa916c836fb997a4ba96b75df01d8a7e53fd74b`。
本轮是在已交付 0.7.0 的基础上新增存档盒子并重新对照，保留
[2026-10-27 六工具审计](war3-tools-audit-2026-10-27.md) 的历史基线与原证据。
旧报告里的候选状态不直接作为当前未完成清单。

## 输入与覆盖

六个原 EXE 的 SHA256 均与旧完整静态清单一致。现代两样本重新对照全部 183 份第一方模块和
1,096 个原索引记录，三个旧样本重判 248 个原索引记录，Hotkeys 复核 38 个功能记录；
合计仍是旧索引的 1,382 个记录，角色、界面、字段和动作彼此重叠，不是独立功能数量。
Hotkeys 的 1,148 个 CArchive 成员全部重新解压核对，第一方 278 个代码对象、28,872 条指令的
静态证据和 158 个功能引用相符。

新增 `魔兽多功能存档盒子1.8.0.9/` 共 45 个目录项（含根）、3 个目录、42 个文件。
全文件共 42,655,112 字节；39 个非 PE 文件共 1,235,848 字节全部读取，前后清单、内容与元数据相同。
四份 ID 表共有 5,365 个记录：单位 1,572、技能 1,823、物品 1,834、科技 136。
29 个商城 key 文件只记录形状、数量与 SHA，不复制实际内容或用于功能。

四成员 ZIP、153 个 CRC 完整 PNG；4 个序列化窗体表的 397 个对象、175 条事件声明均有位置台账。
多编码字符串候选全量留存在本机证据中，其中包含噪声和重叠，未当成功能数量。

没有启动目标 EXE、装载目标 DLL、执行提取字节码、AA 或地图脚本，也没有改动游戏。

## 已存在的能力与本轮差额

完整多选、字段与原字节证据、四码到地图查询、坐标交接、live-report 保存打开比较、
字段/对象/版本参考、GameCache 四布局及英雄字段、文本载体、JASS 前向引用和隐式资源确认
已在当前源码存在，均不重复计为本轮新增。

| 参考来源 | 实际差额 | 本轮实现 |
| --- | --- | --- |
| 存档盒子四份 ID 文本 | 本项目已能导出同款文本，但没有通用读取入口 | `local_id_tables` 严格解码与块读取；`reference --id-table` 和现有参考窗可添加多个本地来源 |
| 盒子提取结果流程及现代 Trainer 存档读取 | 本项目已有递归解析，CLI/GUI 强制要求地图且缺少结构检索窗口 | 地图可选的 `save`、共享完整文件查询、存档工作台和 JSON/TSV/Markdown 导出 |
| 现代 Trainer 文本存码服务 | 本项目底层字节解析已有，公开入口只接受目录 | `savecodes` 接受单文件、日志、明确文本与 stdin |
| Hotkeys 配置/规范化合同 | `.wgc` 和本程序键盘速查没有覆盖外部方案 | `hotkeys inspect/diff` 与离线 GUI，保留原声明、冲突、完整差异和单独兼容推导 |
| 现代 Trainer 的 SLK 证据设计 | 旧 parser 对重复和明示空值有静默覆盖/丢弃 | 原记录/单元格/列证据 API、冲突诊断及空值向实际物化和导出传递 |

外部 ID 的类别仅来自明确声明的表名或显式输入，未知类别保留未分类。
同类同码与内置表重合 1,997 条，其中 1,350 条名称不同；外部记录独立追加，不覆盖地图或基础数据。
源没有声明地图、build、base/custom 时保持未知，不能由这些 ID 表证明物品当前在图中可获得。

存档工作台复用已有解析器，没有新增对盒子私有存档协议的虚构支持。
本次盒子目录内没有用户真实存档；未知范围、损坏载体、来源变化和未做地图关联分别可见。

Hotkeys 采用匹配给定 v2.0.0 EXE 的静态读取合同，没有真实运行配置的往返证明。
原工具非空 target 被重写为 source、旧分组迁移、未知 ID 丢弃、重复 ID 后项覆盖、每方案补齐 42 槽，
均作为兼容推导展示；原声明和未知扩展独立保留。工具运行时输入效果保持 `runtime_verified=false`。

SLK 的当前源码结果通过批处理提取修订 34、live-pack 31、guide 39、client-snapshot 3 换代。
旧输出和用户资产不删除；下一次明确解析会使用新语义。
引号及分号处理核对了 [LibreOffice 的 SYLK 读写实现](https://raw.githubusercontent.com/LibreOffice/core/master/sc/source/ui/docshell/impex.cxx)：
现代生产者与旧 SCALC3 的转义规则分别处理，不把所有字符串套为 CSV 双引号规则。

## 未直接采用的内容

- 旧样本的完整选择/版本和字段框架已在项目存在，待证实时字段需要当前 build 的独立布局和实机证据。
  T5 的 69 个字段角色中 8 个有既有对应，61 个仍需证明；字段名不能产生实时读数。
- 重制版技能/扩展背包/装备/天赋/相机、游戏内改键及速度/物品修改大多依赖主动执行链，
  没有迁入本项目被动读取路径。
- 商城 key、反检测、平台服务器写入、执行 Lua、挂机和解封不成为离线资料工作台的操作。
- 标准运行库菜单、打印/密码/数据库模板和编码噪声不被计成地图或存档功能。
- 外部固定词库、原生 DLL 和整个 ID 数据集没有捆绑分发。用户可明确导入自己的本地文本，保留来源。

## 验证与证据

本轮以独立实现、独立复核、真实四表对账、三个实际 GUI 工作流和完整 Windows 回归收尾。
GUI 的读取、检索、比较、四份完整报告导出，以及窗口关闭后的 Python/Tcl 回调检查
纳入 `gui_tabs` 发行验收，源码与两种新 EXE 执行相同流程。

单图发布、全局报告、清单读取和失败清理；这些修复保留原有来源、身份和原子性检查。
包中独立验收报告记录最终提交、测试数量、完整性、实际输入和产物 SHA256。

本机审计账本、反例、实现报告、复核报告、完整二进制证据与命令日志保存在本轮
`gamexray-tools-adoption-20261028-002130` 任务目录；大型原始证据不进入 Git 或程序包。
