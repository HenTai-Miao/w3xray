# GameXRay 可用方向与落地次序

以下是静态审计后的具体建议，全部尚未实现。只读适配结论与外部原实现是否需主动驻留执行分开记录。完整功能匹配需以六程序最终清单为准。

| 次序 | 建议 | 分类 | 实际增量 | 验证门 |
|---|---|---|---|---|
| P0 | 完整当前选中集合与逐单位只读详情 | 可直接新增 | 在GameXRay已验证Classic选择链继续遍历所有节点，返回selected_units[]；单选兼容selected_unit。GUI列集合后让用户选一个查看现有背包/坐标/来源。 | 合成快照覆盖多选、循环、失效世代、空选、不可读与同码多实例；Classic1.27授权真机多选观察；Reforged继续pending。 |
| P0 | 已具备实时字段的类型、值、地址与未知状态面板 | 可直接新增 | 先为现有单位ID/owner/坐标、六槽物品ID/地址和已证实资源显示类型/值/地址/读取状态及profile来源，增加可复制单条证据。 | 只消费已有report字段；桩数据覆盖0、None、NaN、冲突、未知owner与关闭后过时交付。 |
| P0 | 把已知四码串联真实对象名称与全字段 | 可直接新增 | 复用现有doc/skills/item路由和类别限定目录，把已读/用户选中的四码带到名称、描述和字段详情；目录缺失则保留字面ID及来源。 | 现有GUI code handoff和对象类别/缺源/多码测试扩展；不增加任何游戏调用。 |
| P1 | 已有读数的离线快照比较与证据差异 | 可直接新增 | 对现有输出JSON/快照中的确认字段做显式前后比较，显示来源PID/版本/时间与身份一致性；导出差异报告。 | 同码不同实例、身份更换、字段部分缺失、源快照稳定性和无游戏进程离线场景。 |
| P1 | 档案字段验证与来源覆盖展示 | 可直接新增 | 为所有偏移/地址域增加一致形状校验，显示档案支持模块/来源/校验结果；纯数据不能指定外部代码提供器。 | 数据档案round-trip、所有数值域、未知键/版本、错误类型及无可用链；不复制目标偏移作为可信值。 |
| P1 | 带来源与版本标签的只读目录视图 | 可直接新增 | 借鉴字段目录schema和离线检索UI；资产原样收录前核实来源/许可、SHA256、game build及重复身份，按版本隔离显示。 | 可先独立建立schema/来源检查；实际引入数据需许可和版本证据，不据本审计自动导入。 |
| P2 | HP/MP/三围/攻击/护甲/技能点/物品数量只读字段 | 需要适配 | 借鉴T5已证69字段的字段域/类型/UI分组，独立为GameXRay每个支持build建立只读字段布局与逐成员来源。现SlotItem只有slot/item_addr/code，没有charges。 | 可信格式/反汇编字段证据、合成快照类型/边界测试、授权同局HUD多值/变化回读核验；不靠旧程序声称兼容。 |
| P2 | Reforged/x64被动句柄/选择/字段档案 | 需要适配 | 将具体x64版本身份、模块、布局、选择与字段逐层建证，建立可禁用的纯读取provider；当前resolve_profile的pending保持可见。 | 先要真实授权版本样本和失败证据；不能在无样本时把规划改成已支持。 |
| P2 | 已知存档GameCache字段的只读语义解码 | 需要适配 | 在已验容器解包/地图键关联之上，按具体可证存档记录schema增加英雄/物品字段语义；原始字节/偏移和未解析状态继续保留。 | 格式样本/校验和/记录长度与数量边界、同码跨类、缺字段和损坏记录；源文件前后哈希一致。 |
| excluded | 游戏状态编辑、自动动作与驻留执行 | 超出当前只读边界 | 不把游戏写入、注入/远程线程/Windows hook桥接、倍率/冷却/资源/单位/装备/天赋修改或对游戏发动作纳入当前GameXRay产品。 | 只做边界分类；如确有纯读取目标，另设计无执行路径。 |

- 新装备目录325条；英雄6个、技能27条；技能字段753条、物品字段20条。
- extension-definitions.zip为186成员，manifest声明185文件，185文件哈希全部匹配。该核验不代替来源/许可或目标游戏版本适配。

- 多选集合可沿GameXRay自身已验证Classic选择链补齐，不复制旧修改器裸指针布局。
