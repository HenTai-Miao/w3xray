# 六个 Warcraft III 工具的完整静态审计与 GameXRay 适配结论

审计日期：2026-10-27。GameXRay 源码基线：`ac18ec8d6e02dc36103d6c43cc0de61a0f83ab4e`。
本轮交付是功能梳理、证据与适配设计；GameXRay 的业务代码没有因本审计新增下列候选功能。

## 结论与阅读入口

最有价值的方向是：完整多选列表、已有实时读数的证据面板、活体四码与知识包联动、字段说明与版本目录、离线快照比较、存档字段解码，以及有独立证据的 Reforged 被动读取适配。

目前 GameXRay 的静态地图/战役解析、全量知识包、27 种 CLI 查询、攻略、CASC 文件访问、Classic 已验证读取和完整来源诊断都有自己的实现。外部工具提供的接口、字段名、数据合同和界面需求应与这些现有能力逐项对照。

多个外部工具的 Get/query/读取入口会先装载 DLL、安装钩子、写入命令区或在游戏线程执行。它们可以提供字段和设计线索；现成调用链不能直接作为 GameXRay 的被动 RPM/PrintWindow 读取组件。GameXRay 新增字段必须沿自己的身份、版本与读取证据链独立实现。

## 六个程序分别提供什么

### T1：重制版改键工具 2.0.0

能力包含技能、物品、技能书和商店格位映射、SmartCast、自身施法、方案保存/迁移、冲突检查、启停、聊天状态和后台交付。42 个默认格位、50 个控件家族和全部声明均有清单。

实现包含远端 DLL 装载、游戏线程 hook、内存写入和游戏函数执行。部分 context/readback 查询也经过这个准备过程。`enabled=false`、暂停或聊天状态并不约束 `_native_loop` 的技能键覆盖分支；该分支另以 enforce_hotkeys 与 ability 组为条件。鼠标键可被捕获，但 GUI 将 source 同时作为 target，保存 target 时又不允许 mouse，因此该路径会拒绝鼠标主键。聊天规避是 Enter/Esc 的本地状态机。

精确档案只有 `3.0.0.24268` 和 `3.0.1.24323`；档案自己的验证说明包含 not_run / physical_key_testing_pending。本审计不把这些文字升级成实机验证。

对 GameXRay：配置模型、按键角色与冲突校验、进程出生时间/构建身份、状态和清理设计可参考；游戏内改键桥与输入效果按当前边界单列。

### T2：旧 Trainer 与 R8 修补

功能族覆盖选中集合、单位字段、六格物品栏、技能实例、753 技能字段/20 物品字段、玩家资源、鼠标世界点、属性与技能编辑、物品/实体操作、锁定、50 全局快捷键、ID 目录、双语 UI、Tk 悬停翻译、日志、pending 熔断与 CLI。

活动选中、资源、字段读取实际走 persistent native helper，准备链包含 LoadLibrary/GetProcAddress/SetWindowsHookEx。原生名字表身份并非游戏布局档案。默认进程发现取第一个匹配，不能作为多实例策略借用。物理截图入口直接拒绝，保留 OCR 函数不代表有可用 OCR 读取流程。

R8 悬停词库是 3,395 条六列数据，作用于软件自己的 Tk 控件与 Treeview。基础 ID 数据为 283 物品、833 技能、834 单位，共 1,950；与新版逐条相同。数据和应用代码的来源、许可仍须分别核实。

对 GameXRay：字段类型与适用性、身份/值/地址证据、失败分层和主线程交付可参考；实时属性的被动读取需要自己的布局证据。

### T3：新版 Trainer 2.1.20

功能领域包括 WebView2/RPC 与 Tk、连接/创建时间/地图 epoch、七版 profile、发现与缓存、普通/备用选中、单位属性、技能、经典物品栏、30 格扩展背包、9 装备槽、天赋、方案/批编辑/复制、玩家资源/金矿/科技、相机/鼠标/地形、场景与输入、速度、存码/存档和输出地图/战役定义。

这些领域中的读、计算、呈现、创建、删除、修改及驻留执行已经分别列出。主 bridge 的业务查询也存在远程分配/写入、装载/映射、线程/hook 前置；时钟 DLL 是 hook 计时 API，天赋图标 DLL 会 patch/restore 游戏代码。

可保留为参考的数据实数是：325 件官方装备、6 英雄/27 技能、753 技能字段、20 物品字段、1,191 条隐式 MPQ 路径。嵌套定义包 186 成员，185 数据文件与 manifest 的哈希/长度全部相符。CASC 模块只有静态目录，没有 CASC 存储访问实现。

七版均为 x64 `3.0.*`，不是 Classic 1.27。七个 references.source_digest 陈旧，移除新加的四个 item ability 布局字段后才与原 digest 一致；默认未知 build 发现会在该闸止步。exact build 提前返回，影响范围另列。Web 初始化动作名与通用目录不匹配，实时英雄入口受存档 files.length 门控，部分 diagnostic 缺 DLL marker/query；这些静态阻断没有被计为可运行功能。

对 GameXRay：纯数据 schema、来源/身份/epoch、档案质量、候选与确认分层、离线解析、只读目录、快照/错误/清理交付可借鉴。Reforged 的被动读取是适配项目，现成注入 engine 不能直接承接。

### T4：大象 1.27

界面实际标题为“魔兽争霸毁图器1.27a”。全部 60 选择框、参数与辅助控件已列出。包括资源/属性/单位/技能/物品/全图类修改、热键参数等；53 个选择框有 getter 到直接或解析后虚方法再到 WPM 的静态路径。这不是 53 项实机效果保证。

原始事件表已在与 T5 的格式交叉验证后恢复：137 控件中 21 对象包含 22 声明事件，15 callback 有静态 WPM 可达路径。“无 CD 无蓝耗”的事件读取的是“不会失败”的 checkbox，是明确接线冲突。人口/科技限制项为零事件且没有恢复出精确 ID 使用；另四项效果链不完整。旧报告中“事件表未知”的文字由 crosscheck 附补更正。

对 GameXRay，没有建立可直接接入的独立背包/MPQ/CASC/任务/配方读取功能。可以借用界面分类、参数与效果溯源方法；游戏修改主体按当前边界单列。仍有 117,164 字节代码/数据不透明，生成载荷的部分语义与动态兼容未确认。

### T5：魔兽争霸3修改器_new

该样本按窗口找 PID、找 Game.dll 并精确比较 11 个版本，范围从 `1.20.4.6074` 到 `1.26.0.6401`，没有 1.27 分支。未知 INI 路径绕过正常 setup，“完全支持”的文案早于版本判断，不能据此宣称任意版本兼容。

它按本地玩家选择管理器的 count 读取完整选中集合，在工具列表中挑一个对象查看。69 字段由 57 个普通/技能展开项和六槽物品各名称/数量十二项组成，涉及生命/法力、经验、三围、双攻击、移动、防御、坐标、技能学习和可用技能点等。所谓技能/物品“名称”实际显示 FourCC。四项资源为金钱、木材、当前/最大人口；修改与 300ms 锁定均有写链。

对 GameXRay 的直接启发最明确：完整 selected_units[]、已有字段的类型/值/地址面板、四码到知识包的真名/全字段。69 行中只有 X/Y 和六槽物品身份这八行有现能力对应，其余 61 行需要实时布局适配。读取失败回零、全权限打开、写入和锁值不照搬。

### T6：大象 1.24E / CE Trainer

28 配置动作涵盖初始化、英雄加级、鼠标瞬移、杀单位、迷雾、无敌、冷却、同类型创建/复制、物品创建/删除/充能、缩放、技能、共享控制、12 玩家金木设值、固定光环/被动、拒绝失败、按码增援/物品/科技。

“复制”不等于复制等级/背包等全部状态；充能只操作第 0 背包槽；“全光环/全被动”是固定 8/4 项列表；资源功能是设值，没有独立资源查看。一个无 UI 的显示文字分派只有 ret。About 明确 `1.24.4.6387`，但 28 个 patch 列表全空，没有有效版本字节比对。默认按进程名使用首个匹配。

本体能力依赖写入、远程分配与代码 hook。GameXRay 可取静态动作目录、类别/四码检索案例和证据溯源；不能由该工具的声明把现有 1.24E 公开 RVA 表升级为已验证句柄链。

## 哪些能用于 GameXRay

| 方向 | 现状与新增内容 | 判定 |
|---|---|---|
| 完整当前选中集合 | 自有 Classic 选择链目前在首个可解析成员后返回；可继续遍历并保留每实例身份/坐标/背包/来源 | 可在自有读取链上新增 |
| 已有读数的证据面板 | 当前已读 ID、owner、坐标、背包身份/地址和资源可按类型/值/来源/未知状态统一展示 | 可直接新增展示 |
| 四码与知识包联动 | 名称、说明、全字段、技能、where/drop/near 已有基础；可把集合中每项连续查询和导出 | 已具备基础，增强工作流 |
| 字段解释/别名/版本参考目录 | 现有静态对象字段查询可连接更明确的类型、适用性和来源；目录先审版本与许可 | 可新增离线元数据与 UI |
| 快照离线比较 | 现有 JSON/快照可比较确认字段，保留 PID/出生/地图/时间与不完整状态 | 可新增纯读取分析 |
| 实时 HP/MP/三围/技能点/物品数量 | 当前静态对象字段不等于这些实时值；须新字段布局与同 build HUD 复验 | 需要适配 |
| Reforged/x64 实时读取 | 当前 resolve_profile 为 reforged-pending；七版外部数据只能作线索 | 需要独立被动适配 |
| 存档/英雄缓存语义 | 现有容器与原始字节证据可补已证布局，保留所有 offset/记录与未知 | 需要格式适配 |
| 资源路径与 JASS 静态诊断 | 隐式路径作为当前归档可验证候选；直接调用/前向引用可接既有语言视图与索引 | 可新增只读分析 |
| 编辑/复制/创建/移除/施法/输入/速度/hook | 外部程序大量能力在此，读取准备也可能包含主动执行 | 超出当前只读路径 |

建议一次做成完整链路：**完整选中列表 → 只读证据详情 → 真实名称/字段与获取查询 → 坐标交接 → 快照比较与导出**。先使用已证字段，再独立适配新实时字段与 Reforged。完整实施门见优先级分卷；本报告没有把建议改写成实现完成。

## 上限、身份与授权材料

外部程序存在 Web 前 200 目录/前 100 文件、24/12/64 选中/manager、节点 8192、字符串 256、金矿 4096，以及发现/存码扫描预算等。它们按 UI、wire、经验预算、格式结构分别记账，不能带回 GameXRay 当全覆盖证明。真实编码长度/数量、物理槽位、源身份、路径与分配安全边界继续保留；确需分批的协议要续传或报告不完整。

固定官方 ID/装备目录、支持库许可、包内自报 validated 和界面版本说明分别保留来源。未找到明确第一方许可证的部分标为未知；本审计不授权复制分发整套代码/DLL/词库。数据引用也须保留 game build、SHA、来源和 map 自定义优先规则。

## 完成和未知的边界

全资产清单、第一方 Python 代码对象、界面/动作表及适配对照已建立并逐项核对。原生部分的动态间接目标、T4 部分字节/载荷语义、游戏兼容与真实运行效果仍有未确认项，全部保留在 unknown ledger。完整静态解码不被写成运行通过。

本轮校验包括：6 原文件身份、8 输入快照、1,382 原始 JSON pointer、全部基线 ID、11,723 处源码 AST 定位、交叉表引用的 54 份源码及基线 209 份源码/测试文件哈希。没有执行产品功能测试；源码与测试定位的存在是本轮的检查对象。

工具来源与证据说明：[官方 UPX 5.2.1](https://github.com/upx/upx/releases/tag/v5.2.1) 用于静态解包。REA doctor 记录了当前 provider 缺失，本轮证据来自独立本地静态工具，不使用虚构的 REA Evidence ID。
