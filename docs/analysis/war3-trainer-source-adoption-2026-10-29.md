## 本版采用并实现的逻辑

| 功能链 | 发现的问题 | GameXRay 实现与使用入口 |
|---|---|---|
| 普通/Skin 对象层 | Skin-only 与覆盖地图可能漏对象，却仍显示完整 | 七类 map/campaign 普通与 Skin 层同读；没有 listfile 仍检查固定成员；对象详情、知识包和直接地图参考目录共用 |
| 战役共享对象 | 共享与章节字段的选择、显式基础引用和来源可能断开 | 保留四层覆盖次序、同类别显式基础关系、空覆盖、原字段与完整诊断；章节同码保持独立 |
| v3 对象文件 | 旧实现把额外整数数组当成多组修改记录 | 正确读取 0/1/多项对象头数组与一份修改列表；完整保留列、等级、偏移、原始字节和 trailer |
| 查询与导出 | 低层原始值在某些消费者中可能重新成为当前值 | 字段状态贯穿物品、科技、图标、工具提示、差异和参考目录；当前摘要排除覆盖值，完整证据仍可搜索 |
| 空类别与来源覆盖 | 新导出的完整地图包缺少空英雄表，参考目录无法确认类别为空 | 已选择的八类对象均写完整表头；覆盖表记录逐类别选择状态与完整来源诊断；完整空类别为 0，partial 与未选择状态贯穿参考、查询和统计；修改、删除与交付前变动均重新核验，旧外部包不获得额外完整性证明 |
| 客户端对象缓存 | 旧快照指纹未绑定新读取的二进制层 | 冻结实际命名输入的完整字节，包含普通/Skin、WTS、SLK 和文本；交付/缓存前重核；旧缓存保留并换代 |
| 版本与模块 | 扫文件文本猜版本，模块增长可越界，EXE-only 架构容易误判 | 正式 PE/RT_VERSION 解析、稳定磁盘快照、进程内模块核对、实际架构、动态枚举和完整错误记录 |
| 实时可信度 | 空读被当零值；缺读可能被解释为运行时补丁；检测与快照有时序间隙 | 精确长度、活动标记、世代和自身句柄回链校验；用实际解析快照再次绑定 PE；缺失/变化不保留可信状态 |

## 已有能力与未移植的运行实现

地图/战役解析、空间查询、配方与掉落、完整字段、GameCache、外部 ID、改键方案检查、
只读实时报告和 Windows 两种发行格式已有实现。本次沿用这些入口，不复制第二套 Trainer 界面。

逐调用链检查发现，来源中标为 `read_query`、`diagnostic` 或 `READ_ONLY` 的路径，
部分实际仍注入回调、创建/修改/销毁游戏组或创建/删除临时物品。现代字段 getter 也可能经过原生桥。
这些不能等同于被动读取，不纳入 GameXRay 的只读实时实现。
任意地址写入、原生调用桥、hook、游戏对象创建和修改、装备槽直接写入及修复写入均未移植。

四种基表模式之间存在 2,695 项字段差异；固定 3.0 构建的参考数值不能当作任意地图的权威运行值。
按版本与地图数据模式选择基础表需要对应版本的独立验证，本版没有盲目替换既有基表。
PE、profile 或源码版本相近也不代表运行布局兼容；新增读取健壮性不等于新增全部 Reforged 版本认证。

## 来源项目自身的断点

这些发现保留在功能矩阵中，目标项目未被修改：

- 现代归档搜索 RPC 把返回字典作为路径序列切片；现代内存存档码 RPC 又把报告字典当作候选对象列表。
- Elephant 初始化按钮使用了不被 action 路由识别的名字，专用 RPC 虽然存在，却未接到该按钮。
- 部分 ID/装备/技能搜索只返回前 200 个匹配；完整分页/导出入口与这些入口分开核对，未移植其截断。
- 七个发现记录的 `source_digest` 与当前 profile 的原始或 loader-normalized 摘要都不符，不能依赖 `validated` 声明。
- 两个生成器引用缺失的装备目录生成模块，native 名单生成器也缺失；源码中的生成流程不能据此宣称已可独立重建。
- 发行清单声明 316 个输入，其中 315 个存在且哈希吻合，缺少忽略的 WebView2 bootstrapper。
- 原生桥有 13 个条件 include 缺件，加上 MinHook 的 hde32 共 14 个缺失本地 include；
  map_flags 头存在但没有接线。这不等于默认发行构建必然失败，也不构成那些诊断变体已可用的证据。
- 一些组合操作可能先产生效果，再到达被阻断的旧 getter 或不支持分支；源码没有全局原子回滚证明。

## 验证口径

静态覆盖、合成行为验证、Windows API 验证、真实 GUI 操作和发行产物验收分别保留证据。
合成地图不冒充历史地图；当前 Python 进程的 Windows API 验证不冒充 Warcraft 实机认证。
所有测试和独立验收使用隔离缓存，输入前后核对原始字节及文件身份。

统一交付以冻结源码后的 Windows 全量测试、维护路径质量检查、公共 CLI 和两种发行格式的
实际 GUI/CLI 验收报告为准。分析压缩包保留定向测试与早期失败记录，不能把其中较早的局部计数
拼成最终通过总数。最终报告单独绑定提交、源码清单及发行产物 SHA256。
