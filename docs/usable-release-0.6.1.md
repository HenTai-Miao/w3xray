# GameXRay 0.6.1 使用与验收说明

本版集中修复地图载入、战役切换、查询、导出、后台交付和 Windows 发行链路。
日常使用直接运行程序；开发测试和重新打包属于维护操作。

## 开始使用

Windows 目录版完整解压后，双击 `GameXRay 游戏档案透视器.exe`。
程序与 `_internal` 文件夹必须一起保留。单文件版可单独运行，启动时会展开依赖。

打开 `.w3x`、`.w3m` 或 `.w3n` 后，等待状态栏显示加载完成。
对象编辑器支持名称和四码搜索；场景放置、掉落/获取、触发指令、合成配方等页查看各类证据。
战役从关卡列表切换，攻略、查询与导出使用当前选择的地图及其补充资料。

点击「资料包查询」可使用以下常见模式：

| 目的 | 模式与输入 |
| --- | --- |
| 查物品说明和携带技能 | `item`，输入名称/四码；空词列完整清单 |
| 查单位、英雄、技能 | `units` / `heroes` / `skills`；空词列清单 |
| 查商店及货架 | `shop`；空词列全部商店 |
| 查任务和聊天指令 | `quest` / `cmd`；空词列清单 |
| 查合成与获取途径 | `recipe` / `synth` / `where` / `drop` |
| 查附近对象 | `near`，输入 `X Y 半径`，例如 `0 0 500` |
| 跨字段搜索 | `search`，例如 `物品:攻击 && 火焰` |
| 重跑最近成功查询 | `again`；无效输入不会覆盖成功记录 |
| 保存对象报告 | `export`，输入名称/四码 |

GUI 查询在后台执行，连续请求只交付当前请求的结果；关闭窗口后不交付旧结果。
查询窗口支持 Ctrl+F、Ctrl+A、Esc、右键复制与导出，并保留历史、收藏和窗口尺寸。

## 命令行

在发行目录使用 PowerShell：

```powershell
& '.\GameXRay 游戏档案透视器.exe' --help
& '.\GameXRay 游戏档案透视器.exe' cli 'D:\Maps\地图.w3x' --pack 'D:\报告\本次地图'
& '.\GameXRay 游戏档案透视器.exe' pack-query 'D:\报告\本次地图' item
& '.\GameXRay 游戏档案透视器.exe' pack-query 'D:\报告\本次地图' near '0 0 500' --json
& '.\GameXRay 游戏档案透视器.exe' guide 'D:\Maps\地图.w3x'
```

源码入口为 `uv run gamexray`、`uv run python -m gametool` 或 `uv run main.py`。
例如 `uv run gamexray cli --help`、`uv run gamexray pack-query --help`。

导出目标必须是新目录或空目录。已有目录会明确拒绝，保留全部旧文件；GUI 自动创建新目录。
默认解析和查询覆盖完整输入。显式 `--limit N` 按完整记录限量并报告余量，`0` / `all` / `全部` 表示全量。

## 数据状态与恢复

地图原件只读。损坏对象表、预放置布局、缺失子图或不完整源数据会保留已确认记录和来源诊断，
批处理区分“发布成功”和“知识完整”。组件诊断随知识包保存，主动关闭的提取类别明确标出。
脚本同时保留原始文本与可读副本，索引偏移以原文为依据。

WTG 函数体展开需要匹配版本的 `TriggerData.txt`；缺少时保留已读头部与缺口说明。
只在运行中的游戏支持实时只读探针；多进程需显式 `--pid`，空背包属于有效读取结果。
CASC 真实安装读取依赖本机已安装的数据；路径不明确或证据有歧义时给出诊断。
Windows 不提供 POSIX 目录描述符/交换能力的完整性操作会明确报告平台边界。

## 统一验收

维护者可通过同一个 `acceptance` 入口验收源码和新构建的 EXE：

```powershell
uv run python -m gametool acceptance --map '<地图.w3x>' --campaign '<战役.w3n>' --output '<新的验收目录>' --repeat 5
```

验收覆盖地图和战役载入、知识包导出、27 种查询模式、JSON、报告重开、错误恢复与 again、
批量首次处理和复用、重复载入内容一致性，以及真实 GUI 的 12 个页签和查询弹窗。
Windows 原生依赖及真实 CASC 安装分别单列检查，未提供安装时报告明确列出跳过项。
`coverage_complete` 只有所有检查均通过才为真，不把跳过项目算作完整验证。

验收的缓存、GUI 配置、查询历史和收藏使用私有临时目录，结束后恢复调用方环境。
实际发布验证结果、输入保护证据、产物哈希和提交号写入本次独立验收报告。
