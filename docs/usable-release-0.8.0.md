# GameXRay 0.8.0 本地资料与存档工作台

当前维护 Windows x64，提供目录版 ZIP 和单文件 EXE。目录版解压后运行
`GameXRay 游戏档案透视器.exe`，保留旁边的 `_internal`。本页的功能均通过本地文件使用；
实时探针单独发起，不会因打开下面的窗口而连接游戏。

## 地图和已有查询

打开 `.w3x`、`.w3m` 或 `.w3n` 后浏览对象、触发器、场景、任务与来源诊断。
使用「攻略速查」查看商店、配方、掉落和任务线索，再用「包查询」按名称、四码和坐标深入查询。
没有打开地图时，从「数据工具 → 打开本地资料包查询（离线）」选择已有资料包。
完整多选、字段证据、查询坐标交接、实时报告保存与比较继续可用，步骤见
[0.7.0 既有工作流说明](usable-release-0.7.0.md)。该文中的历史验收不代替本版报告。

批量导出的单图和全局报告发布支持 Windows 扩展路径，保留完整清单校验与原子发布。
关闭查询窗口时会取消该窗口的延迟回调和过期结果交付，其他窗口继续正常工作。

## 导入盒子兼容 ID 文本

进入「数据工具 → 字段 / 对象 / 版本目录」，点击「加 ID 文件」或「加 ID 目录」。
可以添加多个明确的本地来源；「清空 ID」移除外部来源，内置目录与知识包继续可查。
文件选择会记忆，读取失败会显示完整诊断，可以清空失效来源重新选择。

原存档盒子的四表位于 `魔兽多功能存档盒子1.8.0.9/提取的ID/`。
支持 `单位ID.txt`、`技能ID.txt`、`物品ID.txt`、`科技ID.txt` 中的
`ID：`、`名字：`、`描述：` 标签块，以及本项目「导出 ID」产生的同款文本。
UTF-8、文件首 UTF-8 BOM、cp936 与 gb18030 均按严格编码读取；描述的多行、空行、
颜色/换行标记、同名异码、同码多记录和冲突原文保留。

这些条目显示为 `external / external-unverified`，保留源文件、编码、完整 SHA256、
原始文本/字节、行号和字节区间。外部名称与基础目录、地图自定义对象分别保留。
来源没有声明地图、build、基础 ID 或自定义状态时，不补出这些事实。
目录导入只处理已声明的 ID 文件；其他文件保留未导入说明，不读取商城 key 数据。

```powershell
& '.\GameXRay 游戏档案透视器.exe' reference --id-table 'D:\资料\提取的ID' --kind objects --json
& '.\GameXRay 游戏档案透视器.exe' reference '攻击 && 火焰' --id-table 'D:\资料\物品ID.txt' --json
& '.\GameXRay 游戏档案透视器.exe' reference --pack 'D:\资料\地图包' --id-table 'D:\资料\提取的ID' --json
```

关键字使用现有 Boolean 查询语言，空词列全量。`--id-table` 可重复。
显式 `--limit N` 选择完整条目，诊断始终完整；`0`、`all`、`全部` 表示全量。
JSON/Markdown 导出保留全部所选条目和来源台账，输出应放在输入资料目录之外。

## 无地图存档工作台

进入「数据工具 → 离线存档工作台」，选择一个文件或目录，点击「读取 / 刷新」。
「分析真实存档文件」「分析真实存档目录」也会进入同一个工作台。
目录、完整文件列表、类型、来源状态、每个文件的全部结构和原始证据在窗口内查看。
搜索支持 Boolean 表达式；类型与数量筛选按完整文件记录选择。

地图关联是可选步骤。留空时显示「未做地图关联」，仍解析已支持的容器、GameCache、
文本载体和码候选；不需要启动游戏或安装客户端。选择地图后按这次独立加载的来源做静态关联，
不会复用主窗口已关闭或切换后的地图对象。

JSON、TSV、Markdown 导出包含来源哈希、完整结构、偏移、原字节与全部诊断。
坏容器、未识别二进制、未完成文本载体、未知区域、不可读与变化来源都标明未完成。
已变化文件的旧快照放在 `unverified_files`，不冒充当前稳定数据。导出会再次复验来源；
连续变化导致无法建立稳定报告时，会明确拒绝发布，可重新读取后再导出。

```powershell
& '.\GameXRay 游戏档案透视器.exe' save --save 'D:\存档' --output 'D:\报告\存档.json' --format json
& '.\GameXRay 游戏档案透视器.exe' save --save 'D:\存档' --query '英雄 || 等级' --limit all --output 'D:\报告\存档.md' --format md
& '.\GameXRay 游戏档案透视器.exe' save --map 'D:\地图\示例.w3x' --save 'D:\存档\Campaigns.w3v' --output 'D:\报告\关联.json' --format json
```

保存的是文件中可确认的数据；码候选不等于服务器已接受的有效存档，静态英雄字段不等于当前游戏状态。
平台私有协议、作者加密、服务器写入和运行外部脚本不由该读取流程推定。

## 存码文件、日志和明确文本输入

`savecodes` 接受一个文本文件或目录，包括 `.log`；也可明确选择 `--text` 或 `--stdin`。
没有指定输入时显示用法并结束，不会默认等待读取标准输入。
输出保留载体、命令候选、完整字节和字符偏移、编码、原文、SHA256 和诊断。

```powershell
& '.\GameXRay 游戏档案透视器.exe' savecodes 'D:\存档\记录.log' --json
& '.\GameXRay 游戏档案透视器.exe' savecodes --text='-load EXAMPLE123' --json
'-load EXAMPLE123' | & '.\GameXRay 游戏档案透视器.exe' savecodes --stdin --json
```

## 离线检查与比较改键方案

进入「数据工具 → 检查 / 比较改键方案（离线）」，明确选择 `config.json`，点击检查。
有旧文件时可以比较两份方案；查看原声明、冲突、完整 JSON 和兼容推导，并导出独立新报告。
来源和筛选改变后，旧后台结果不会替代新选择；导出保留原配置和已有报告。

读取合同来自给定 `War3ReforgedHotkeys-v2.0.0.exe` 的静态证据。
原声明与原工具补齐的每方案 42 槽分别列出：旧组名迁移、非空 target 改为 source、
未知 ID 被忽略、重复 ID 后项覆盖及缺槽补齐均可见。未知字段、重复 JSON 键、重复绑定、
数值原始拼写及原字节仍保留，源文件不会因此改写。

```powershell
& '.\GameXRay 游戏档案透视器.exe' hotkeys inspect 'D:\方案\config.json' --json
& '.\GameXRay 游戏档案透视器.exe' hotkeys inspect 'D:\方案\config.json' --profile 'Default' --output 'D:\报告\检查.json' --json
& '.\GameXRay 游戏档案透视器.exe' hotkeys diff 'D:\方案\旧.json' 'D:\方案\新.json' --output 'D:\报告\差异.json' --json
```

退出码 0 表示完整且没有问题；1 表示完整检查发现问题或比较发现差异；2 表示输入、身份或完整性问题。
报告保留 `runtime_verified=false`：静态读取合同不是官方导出认证或游戏实机效果保证。
该窗口不应用改键、不安装钩子、不发送输入，也不自动搜索用户的真实 AppData 配置。

## SLK 地图来源与空值

SLK 解析保留原始记录、列、单元格、稀疏坐标、字段位置和完整诊断。
同一单元格、表头、对象或多文件来源发生冲突时，保留各方证据及不可确认范围；
不取最后一条作为真值。明确编码的空值可覆盖继承；明确清空名称时，使用四码作为显示标签，
原名称字段仍为空。旧解析缓存随输出语义换代，旧导出资产继续保留。
价格、物品技能、货架与科技费用查询共同保留这些未确认状态；原生表字段与对应二进制字段
采用同一元数据角色。更高优先级的明确值可以解除阻断，旧冲突原文仍可查。

维护者使用隔离运行缓存，执行 Windows 全量回归、完整质量检查、真实四份 ID 表对账、
三个实际 GUI 工作流，以及新目录版和单文件版的发行验收。
测试数量、源码提交、运行环境、实际输入范围和每个产物的 SHA256 以本版独立验收报告为准。
