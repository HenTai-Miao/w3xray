## 图标覆盖口径

图标通过两条互补通道提取：

- 具名通道：从对象图标字段收集路径，依次查询地图、战役外层和经典客户端 MPQ，并在索引中保留对象分类、ID、名称、请求路径、解析路径、真实来源和 SHA-256。
- 匿名通道：从提取账本中读取可静态证明为 BLP 的匿名块，命名为 `block_XXXXXX_<sha8>.blp`，不猜测原始文件名或对象关联。

当前结果包含：

- 32,397 条具名逻辑记录。
- 46,137 个匿名 BLP。
- 78,534 次原始写出成功和 78,534 次 PNG 转换成功，已导出记录的失败数为 0。
- 78,372 份唯一原始文件和 78,372 份唯一 PNG。

逻辑记录比唯一文件多 162 条，是因为同一资源同时被对象以 `.tga` 和 `.blp` 引用，而客户端静态解析都落到同一个、SHA-256 相同的 `.blp`。索引保留两条引用证据，磁盘只保留一份相同内容；这不是图标丢失。

另有 9,679 个具名路径无法在地图或客户端中静态证明对应文件，因此只计入“具名未解析”，不会伪造文件名或绑定到匿名块。

## 描述完整性

`对象描述.tsv` 为每个对象或显式等级保留：

- 分类、对象 ID、基础 ID、名称和是否自定义。
- 原始提示与原始完整说明。
- 去除 Warcraft 颜色码并展开换行后的可读文本。
- 提示来源、说明来源和完整性状态。

状态只有四种：

- `地图原值`：地图显式提供非空值。
- `客户端补全`：地图未覆盖，值来自经典客户端基础对象数据。
- `地图明确清空`：地图显式把字段设为空，客户端值不得覆盖。
- `源数据缺失`：地图和客户端均没有文本，不生成替代说明。

当前 136,787 条记录中：地图原值 77,427 条、客户端补全 23,895 条、地图明确清空 61 条、源数据缺失 35,404 条。TSV 使用标准制表符分隔引用规则；即使原始 Warcraft 文本以未闭合双引号开头，也能保留原值并由 Excel/Python CSV 等标准解析器稳定读取。

## 断点续跑与安全边界

- 只有源 size、mtime-ns、SHA-256、输出 schema 和必需报告都匹配的“完整”结果才直接跳过。
- “部分完成”和“受限”结果会重新审计；失败结果默认重试。
- 地图之间不并行，图片逐个解码并立即关闭，避免图标缓存随数量增长。
- 不执行地图脚本、历史 EXE 或 DLL；不加载 `Game.dll`，不做注入、进程内存读取或运行时解密。
- 输出路径拒绝绝对路径、父目录穿越、符号链接父目录和不安全冲突。

## 已知限制

- 删除名称哈希的匿名块只能按块编号和内容哈希导出，不能在没有证据时恢复原路径或对象关系。
- 缺少静态密钥的加密块只会报告为受限证据，不尝试运行时绕过。
- 地图和客户端都没有提供的说明只能标记为缺失。
- “部分完成”表示所有可恢复结果已经发布，但仍有明确、可审计的静态证据缺口。
