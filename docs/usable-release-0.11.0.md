# GameXRay 0.11.0 使用说明

本版维护 Windows x64，提供目录版 ZIP 与单文件 EXE。完整解压
`gamexray-v0.11.0-windows-x64.zip` 后运行 `GameXRay 游戏档案透视器.exe`，
保留旁边的 `_internal` 文件夹。地图、战役、知识包、参考库、存档和脚本分析均可离线使用，
无需安装 Python。实时探针仍需要运行中的对应游戏。

## 地图资源完整导出

打开地图后点击顶栏「导出全部」。程序从归档目录、已知成员及可确认的资源引用恢复成员，
再将尚不能命名的块保留在 `Unknown` 或 `UnknownRaw`。读取与导出不改写原地图。

本版修复同名文件存在多个 locale/platform 时导出内容错误的问题。
每条命名证据必须命中归档的实际哈希探测链，并读取该条目对应的物理块。
默认成员可按原路径导出；其他成员或输出路径发生冲突时，保存在
`RecoveredNames/blocks/`，名称包含块号、locale 和 platform，不会用默认语言内容顶替其他成员。

加密但名称已经确认的脚本也参与引用发现。由脚本找到模型后，继续读取已确认模型中的贴图等引用。
`.mdl` 到 `.mdx`、模型的 `_Portrait.mdx`、导入目录前缀和模型内 `MODL` 名称只提供待核验候选；
只有实际哈希和成员读取均确认后才导出为命名文件。UTF-8 与配置的旧版编码沿用严格解码边界。
循环引用按已经检查的物理块和候选去重，没有按资源条数提前停止。

`RecoveredNames/manifest.tsv` 保留块号、locale、platform、哈希表位置、候选名称、
实际输出路径、字节数、识别类型与 SHA-256。不同候选指向同一块时仍保留名称歧义证据；
不能确认名字或解密的原块继续保留。已有恢复输出和清单发生同名冲突时使用新名称。

「导出全部」与知识包导出是不同入口：前者保留归档成员，后者生成供查询使用的解析资料。
源码调用可使用 `gametool.api.export_all_files` 或 `export_loaded_map_files`；
`cli --pack` 生成知识包，不能用它的成功结果证明资源恢复完成。

## 科技字段分类查询

从「数据工具」打开参考目录，类型选择 `fields`，类别选择「科技」，刷新即可查看
37 个有明确科技类别声明的字段。无需先打开地图，也不依赖 Trainer 或外部编辑器目录。
输入名称、四码或字段内容可继续筛选；多选、全选、完整详情及 JSON/Markdown/TSV 导出共用同一份数据。

```powershell
& '.\GameXRay 游戏档案透视器.exe' reference --kind fields --category 科技 --json
& '.\GameXRay 游戏档案透视器.exe' reference --map 'D:\地图\示例.w3x' --kind fields --category 科技 --json
```

本次补全的是类别声明及其来源。37 个科技字段的类型原本已有，不能把它们算作新增实时属性。
版本化参考共保留 1,294 条类别声明，对应 1,284 个字段身份；10 个同码多类别字段保留全部类别。
原有 1,257 条技能、单位、物品元数据及 727 项常量继续保留。

详情展示类别来源、编辑器版本、生成输入及参考差异。已有人工标签和历史 seed 的优先级不变，
11 项科技标签翻译差异明确记录；不会用另一版本的翻译或范围静默覆盖现有值。
版本化元数据用于解释字段，不代表当前地图的科技等级、价格或运行时效果。

## 脚本诊断

打开地图，在地图信息中的「脚本诊断」查看本地状态、同步修改和 JASS 调用证据。
命令行查看地图时也显示同源诊断：

```powershell
& '.\GameXRay 游戏档案透视器.exe' cli 'D:\地图\示例.w3x'
```

诊断先按已知 JASS/Lua 语言识别注释、字符串、实际调用和函数作用域。
注释或字符串里提到 `GetLocalPlayer`、相机或 Dz API 不再等同于调用；
嵌套条件结束后仍位于外层本地分支的同步修改不会被遗漏，普通本地玩家读取也不会污染下一函数。
条件分支、绑定与未知环境的证据保留来源、位置及原文，实际调用名称区分大小写。

这些输出是静态审阅提示。它们不执行地图，不等同于游戏内联机验证，
也不会因没有命中已知规则就声称脚本语法、类型或所有游戏行为已经通过。
原有 JASS 前向调用证据继续保留。

## 既有功能与本次采用范围

Skin 对象覆盖、完整二进制字段、参考目录批量导出、文本存档编码选择及被动实时读取的
使用步骤见 [0.10.0 使用说明](usable-release-0.10.0.md)。

本版对提供的 Trainer 2.1.22 做静态容器、Python、前端、原生组件和脚本数据审查，
具体功能与采用对照见 [2.1.22 审计与实施说明](analysis/war3-trainer-2.1.22-adoption-2026-10-29.md)。
本次没有引入 Trainer 的 DLL、内存写入、火龙地图注入或 pjass 可执行文件。
部分来源功能存在选项未生效、停止时序或检查器压制错误仍成功等问题，报告保留准确边界。

完整 Windows 回归、公开入口和真实 GUI 流程分别验证；目录版与单文件版各有与实际 EXE 绑定的结果。
最终交付报告记录源码提交、输入清单、验收项目及 SHA-256。失败、跳过或未请求的真实游戏/CASC
测试不会被计入通过项。历史用户配置、缓存、收藏、源地图和此前发行目录保持独立。
