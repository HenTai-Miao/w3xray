# 完整静态提取与批量验收设计

- 日期：2026-07-13
- 状态：用户已批准规格，进入实施
- 目标项目：`w3xray`

## 背景与已确认事实

当前版本已经具备以下能力：

- 对用户当前提供的 27 张地图完成普通 CLI 与当前地图快照回归，结果为 27/27；测试前后源文件 SHA-256 不变。
- 兼容标准 MPQ、HM3W/UserData 包装、对齐诱饵头、经典格式 32 位表偏移回绕和截断 block 表。
- 通过内部 `(listfile)`、内置路径、导入清单与外部 listfile 合并发现文件名。
- 对匿名 block 尝试恢复标准 MPQ 文件密钥；可解码内容写入 `Unknown/`，不可解码原始负载写入 `UnknownRaw/`。
- 作者明文补充包以源地图 SHA-256 和逐文件 SHA-256 绑定，不执行补充包中的代码。
- 当前地图入口只读取操作系统可见的路径和磁盘证据，再解析只读快照。

“任意未知地图都完整提取”不能等价为“任意密文都能无密钥解密”。如果明文只存在于游戏进程内存，静态工具无法从磁盘字节推导它。本设计完整实现可审计的静态处理链：能恢复的全部恢复，不能恢复的保留原始字节并准确报告，绝不把部分结果标为完整。

## 目标

1. 每个 `.w3x/.w3m/.w3n` 输入都得到一个确定的提取结论：`complete`、`partial`、`encrypted_blocked` 或 `damaged`。
2. 对每个可盘点的 live MPQ block 记录其路径、来源、解码状态、大小、SHA-256 和失败原因。
3. 支持经源地图哈希绑定的兼容数据包，导入外部名称、有效 MPQ 文件密钥和已验证明文文件。
4. 提供从其他工具已导出目录创建兼容数据包的只读命令；不启动或嵌入该工具。
5. 提供目录批量提取命令，逐图导出并生成机器可读、可复核的总报告。
6. CLI、GUI、资料包和批量报告使用同一提取状态与证据模型。
7. 保持源地图只读、资源有界、跨平台和现有公开入口兼容。

## 非目标与强制边界

- 不读取游戏内存，不 dump 进程，不加载 `Game.dll`，不注入 DLL，不申请提权。
- 不执行地图脚本、loader、旧软件、兼容包脚本、插件、DLL 或任意可执行载荷。
- 不绕过平台反作弊或访问控制，不实现数据级运行时解密。
- 不宣称能从未知强加密密文中无密钥恢复明文。
- 不修改、重打包或覆盖源地图。
- 本次实现不自动推送、发布 GitHub Release 或替用户分发第三方地图内容。

## 方案

采用“现有 MPQ 解析器 + 只读兼容证据 + 逐 block 账本 + 批量编排”方案。兼容数据只能提供静态字节、名称和密钥；它不能加载代码。所有入口最终使用同一 archive reader 和同一状态聚合器，不新增一套结果口径。

## 兼容数据包

### 布局

兼容包是普通目录：

```text
bundle/
  w3xray-compat-bundle.tsv
  files/
    war3map.j
    ...
```

清单是 UTF-8 TSV，格式固定为：

```text
W3XRAY-COMPAT-BUNDLE\t1
source_sha256\t<64 位小写十六进制>
name\t<MPQ 内部路径>
file\t<MPQ 内部路径>\t<文件 SHA-256>
mpq_key\t<十进制 block 索引>\t<8 位十六进制有效文件密钥>\t<明文 SHA-256>\t<内部路径或 ->
```

规则如下：

- `source_sha256` 必须与本次源地图完全一致，否则整包拒绝。
- `name` 只补充候选路径；只有 MPQ hash 表确认存在时才采用。
- `file` 的正文位于 `files/` 下相同相对路径，逐次读取都复核文件身份、大小与 SHA-256。
- `mpq_key` 是传给 MPQ block reader 的最终 32 位文件密钥；带 `FIX_KEY` 的 block 不再二次变换。
- `mpq_key` 解码后必须与声明的明文 SHA-256 一致，错误密钥不得产生伪明文。
- `mpq_key` 的最后一列必须是安全内部路径或单个 `-`；提供路径时必须与对应 block 的 hash 证据一致，写 `-` 时按稳定的 `Unknown/` 路径发布。
- 内部路径统一使用安全相对路径语义；绝对路径、驱动器、UNC、`..`、空组件和规范化重复名拒绝。
- 清单最多 2 MiB、`name` 最多 100,000 行、`file` 最多 10,000 行、`mpq_key` 最多 262,144 行；单个明文最多 256 MiB，明文总量最多 512 MiB。所有目录和文件符号链接拒绝。
- 只接受 regular file。FIFO、设备、socket、路径替换和验证后的内容变化均失败关闭。

现有 `w3xray-author-bundle.tsv` v1 保持兼容。两种格式在内部归一化为不可变的补充证据模型；作者明文包不必迁移。

### 证据优先级与冲突

单个 MPQ block 按以下顺序尝试：

1. 由确认名称使用标准 MPQ 派生密钥读取。
2. 使用现有匿名扇区偏移表算法恢复密钥。
3. 使用兼容包中绑定到该 block 的静态 MPQ 密钥读取并校验明文哈希。
4. 使用哈希已验证的兼容包/作者包明文文件。
5. 仅保存源容器中的原始 block 负载到 `UnknownRaw/`。

已有作者明文包保持当前“显式明文覆盖同名归档成员”的语义。每次覆盖都写入账本，不再只在 `MapData.author_bundle_files` 中保留一个名称列表。兼容包同名明文也视为显式覆盖；若归档原成员可读且哈希不同，使用兼容包内容但记录 `plaintext_override_conflict` 警告。两个补充来源不得同时声明同一规范化路径或同一 block；冲突在解析前拒绝，不能按加载顺序决定。

## 逐 block 提取账本

新增不可变账本条目，至少包含：

- `block_index`：基础 MPQ block 索引；纯补充文件为 `null`。
- `internal_path`：可靠路径或稳定的 `Unknown/UnknownRaw` 相对路径。
- `state`：`decoded`、`supplemented`、`raw_only`、`encrypted_blocked`、`damaged`。
- `source`：`archive_named`、`archive_recovered`、`compat_key`、`compat_plaintext`、`author_plaintext` 或 `raw_payload`。
- `declared_size`、`written_size`、`sha256`、`encrypted`、`error_code`、`detail`。

账本由 archive 层产生，资料包发布层只增加写入结果，不能反向把写入成功当成解码成功。输出包含：

- `提取结果.json`：版本化机器可读结果、源地图身份、总状态和全部条目。
- `提取结果.tsv`：便于人工筛选的逐 block 表。
- 现有 `提取完整性.txt`：改由同一账本格式化，避免口径漂移。
- 现有 `Unknown/`、`UnknownRaw/` 与 manifest：继续保留，路径与账本一致。

## 总状态定义

- `complete`：基础容器可可靠盘点；每个 live block 均得到经过结构检查的明文字节；所有补充文件哈希有效；所有请求的输出均成功写入。匿名但已解码并写入稳定 `Unknown/` 路径的 block 仍属于字节完整，报告另列“名称未知”数量。
- `partial`：容器可盘点，但至少一个 block 只有原始负载、补充输出缺失，或非关键输出写入失败；同时不存在更精确的纯加密阻断分类。
- `encrypted_blocked`：容器可盘点，未恢复的 block 均因加密且缺少有效静态密钥/明文；不存在结构损坏证据。
- `damaged`：容器无法可靠盘点，或 block/table/sector 结构损坏导致不能确认完整集合。

聚合优先级为 `damaged` > `partial` > `encrypted_blocked` > `complete`；但当所有未恢复项都是明确加密时使用 `encrypted_blocked`，不会被笼统归入 `partial`。报告始终保留全部明细，状态不能掩盖已成功恢复的文件。

## 外部导出目录导入

新增命令：

```text
python main.py compat build <源地图> <已导出目录> --output <兼容包目录>
```

命令只读取源地图和已导出目录，生成 `file` 行与哈希，不执行产生这些文件的软件。扫描拒绝符号链接，限制深度、文件数、单文件和总字节；输出目录必须为空或不存在，并通过私有 staging 目录原子发布。重复规范化路径、大小写冲突和不安全路径使整个构建失败。

可选的 `--listfile` 复用现有外部 listfile 格式。`--keyfile` 是 UTF-8 TSV：首行必须为 `W3XRAY-MPQ-KEYS<TAB>1`，后续每行严格包含 block 索引、8 位十六进制有效文件密钥、明文 SHA-256，以及安全内部路径或单个 `-`。构建阶段立即对源地图试解并复核哈希，无法验证的 key 不写入兼容包。

## 单图入口

- CLI `main.py cli` 与 `main.py current` 新增 `--compat-bundle <目录>`；可与现有外部 listfile、游戏数据和作者明文包组合，但补充来源冲突时拒绝。
- GUI“数据工具”新增“选择/清除兼容数据包”，保存路径但每次加载都重新校验源地图哈希和包身份。
- `MapLoadContext` 只携带已验证的不可变配置或路径，不在解析器深层读取 GUI 状态。
- 战役父容器的兼容包不会自动套用到子图；子图需要按自身 SHA-256 匹配的独立兼容包，避免错误覆盖。

## 批量提取入口

新增命令：

```text
python main.py batch <地图目录> --output <输出目录> [--compat-root <兼容包根目录>] [--listfile <路径>] [--game-data <路径>]
```

行为固定为：

1. 只扫描 regular `.w3x/.w3m/.w3n`，按规范化相对路径排序；最大深度 5、最多 10,000 张，符号链接不跟随。
2. 扫描前记录每张地图身份与 SHA-256；处理后重新核对，变化的源文件标为 `damaged/source_changed`，对应 staging 输出删除。
3. `compat-root` 下的兼容包按 `source_sha256` 建立有界索引；重复哈希绑定使批次在处理前失败。
4. 每张地图写入独立目录，目录名包含安全文件名和源 SHA-256 前 12 位，避免同名覆盖。
5. 每图先写私有 staging 目录，完成后原子发布；失败不能留下伪完整目录。
6. 根目录生成 `batch-result.json` 与 `batch-result.tsv`，包含每图状态、计数、输出路径和首个失败原因。
7. 退出码：全部 `complete` 为 0；存在 `partial/encrypted_blocked/damaged` 为 1；参数、输出安全或批次级系统错误为 2。
8. 默认串行处理，保证内存和句柄上限；本次不引入并行开档。

## 错误处理与资源安全

- manifest/key/listfile 的语法或身份错误在解析地图前失败，并输出单行稳定错误码。
- 单 block 解码错误隔离记录，不能中止其他独立 block 的恢复。
- 表无法盘点、源文件变化和输出根不安全属于地图级失败。
- 所有 mmap、文件句柄、当前地图快照、staging 目录和兼容包句柄在成功或异常路径均关闭/清理；清理失败不得遮蔽原始错误，但必须进入诊断。
- 解压预算、表项预算、路径预算、资料包预算和战役子图预算不因兼容包而放宽。
- JSON/TSV/终端/GUI 文本统一清理控制字符；用户路径不得直接进入 traceback 或终端控制序列。

- `name/file/mpq_key` 每种行的成功与失败；错误 key、错误 block、错误明文 SHA-256 必须拒绝。
- 标准加密单元 block、分扇区 block、压缩 block、`FIX_KEY` block 使用显式 key 可还原；错误 key 不产生输出。
- 账本逐项来源、状态、哈希和错误码稳定；聚合四种状态及优先级完整覆盖。
- 作者明文包 v1 继续工作，并产生新的来源账本。
- 批量扫描深度、数量、排序、扩展名、symlink、同名、源变化、staging 清理和三种退出码。
- JSON schema 版本、TSV 列和中文文本快照稳定。

### 集成测试

- 标准地图得到 `complete`。
- 保护头地图仍可完整读取。
- 匿名加密 block 可自动恢复时为 `complete`；只有原始负载时为 `partial`。
- 缺 key 的纯加密阻断为 `encrypted_blocked`；加入正确兼容包后变为 `complete`。
- 损坏表或扇区为 `damaged`，其他可读成员仍导出并记录。
- 外部导出目录构建兼容包，再由单图 CLI、当前地图 CLI 和 GUI 加载。
- 战役父图与子图按各自 SHA-256 选择补充来源，不交叉套用。
- 资料包中的 JSON、TSV、完整性文本、Unknown manifest 与实际输出相互一致。

### 真实地图与发布级验收

- 固定桌面 `Maps` 全目录源文件路径、大小、mtime 和 SHA-256。
- 对全部地图运行单图 CLI、当前地图快照链和新批量命令；批量报告中的地图数必须与扫描集合一致。
- 测试后重新核对所有源地图身份和 SHA-256，任何变化均失败。
- 当前 27 张地图不得回归；新增失败样本必须先固定哈希和期望分类，再实现对应静态兼容。
- 完整 pytest、compileall、Ruff、BasedPyright、仓库 no-excuse 检查和 `git diff --check` 全部通过。
- Windows x64、macOS x64/arm64、Linux x64 workflow 运行测试、打包和成品 acceptance；Windows ZIP/EXE 与 POSIX 归档均从成品运行批量帮助/小型 fixture 验收。

## 实施约束

- 生产 Python 文件保持单一职责和严格类型；新增文件不超过仓库 250 行纯代码门槛。
- 先以失败测试锁定每项行为，再做最小实现；不得为了“覆盖更多”放宽现有安全上限。
- 复用 `MapArchiveReader`、`MapLoadContext`、`bounded_file`、`safe_output`、`KnowledgeWriteReport` 和现有 MPQ block reader，不复制第二套解析器。
- 保持现有 CLI 参数、作者明文包、GUI 配置和资料包字段向后兼容。

## 完成标准

1. 规格中的每个生产行为都有自动化测试。
2. 每个输入都得到真实状态和逐 block 证据，不存在静默丢失或伪完整。
3. 正确静态 key/明文能够把对应阻断图变为完整；缺少材料时准确标记阻断并保留原始负载。
4. 新批量命令可对 Maps 全目录一次提取、生成总报告并以退出码反映是否全完整。
5. 所有源地图在测试前后字节完全一致。
6. 全量本地与跨平台成品验收通过后，才可声明实现完成。
