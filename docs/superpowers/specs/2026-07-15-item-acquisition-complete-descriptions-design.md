# 装备掉落、获取关系与完整描述展示设计

- 日期：2026-07-15
- 状态：书面规格待用户复核
- 项目：`w3xray`
- 已选入口：对象详情页 + 独立“掉落/获取关系”列表 + TSV 导出

## 背景与已确认事实

当前 39 张地图已经发布 79,078 条图标记录和 139,440 条描述记录，图标原始文件与 PNG
均已成功写出。现有描述 TSV 不截断长文本，但只为每个对象或等级选取一组“提示/说明”，
会遗漏学习、关闭、Buff、复活、唤醒、编辑器描述等其他文本角色。`,`、`-`、`""` 等占位
内容也可能被误算成有效说明。

当前关系数据存在以下缺口：

- `war3mapUnits.doo` 中的单位掉落集合被读取后丢弃。
- `war3map.doo` 中的可破坏物掉落被扁平化，丢失随机组和组内顺序。
- 对象引用已经能识别商店的 `Sellitems`、`Makeitems` 以及物品的 `abilList`、
  `cooldownID`，但没有形成可查询的装备获取与技能关系。
- 商店对象没有关联预放置实例、玩家和坐标。
- 合成配方已有尽力识别结果，但缺少源文件、函数、行号、可信度、详情页反向入口和 TSV。
- 脚本调用、函数和触发注册已有底层索引，但还没有形成带证据等级的物品奖励关系。

本机当前没有可用的 Warcraft III 客户端数据目录。此前发布结果中有 1,625 个无冲突的唯一
基础对象/等级文本键，可作为受校验的补全缓存，但不能冒充当前客户端来源，也不能覆盖地图
作者的明确值或明确清空。

## 目标

1. 在怪物或其他来源对象详情中完整列出它能掉落、出售、持有或奖励的装备。
2. 在装备详情中列出所有已证明的获取方式、位置、概率、合成材料及携带技能。
3. 新增独立“掉落/获取关系”页，支持搜索、类型筛选、可信度筛选和对象反向定位。
4. 为批量结果和知识包导出完整描述、掉落/获取关系和装备技能 TSV。
5. 源中存在的文本必须 100% 原样保留，同时提供不改变原值的可读版；任何入口都不得截断。
6. 对未知、冲突、来源不可用和静态分析无法证明的内容如实标记，不编造名称、描述或掉落。
7. 继续保持源地图只读，不执行地图脚本、历史 EXE、DLL 或其他载荷。

## 非目标

- 不运行地图来观察实际掉落，也不读取游戏进程内存或进行运行时解密。
- 不把任意 `CreateItem` 调用自动宣称为某个怪物的直接掉落。
- 不为动态计算、混淆或加密脚本猜测无法静态证明的物品 ID、概率或触发条件。
- 不修改或重新打包源地图。
- 不在本次工作中重做对象编辑器、图标提取器或无关报表。

## 方案选择

采用用户选择的方案 1：同一份只读关系索引同时服务对象详情页、独立关系页和 TSV。与“只在
详情页显示”相比，它能跨对象检索和审计；与“只导出报告”相比，它能在 GUI 中直接从怪物查
装备、从装备反查来源。三个入口不各自扫描数据，避免结果口径漂移。

## 核心架构

### 模块边界与兼容接口

实现保持解析、索引、展示和导出四层分离：

- 完整文本模块只负责从对象候选、客户端字段和缓存建立不可变文本证据与解析状态，不导入 GUI
  或文件写入代码。
- 关系模型模块只定义不可变对象引用、实例引用、证据位置和关系记录；关系构建模块分别消费
  DOO、对象引用、配方和脚本/触发索引，再汇入一个索引构造器。
- GUI 展示模块只查询文本/关系索引并格式化完整内容，不重新解析字段或脚本。
- TSV 模块只序列化索引记录；批量处理和知识包编排只负责安全写入与清单登记。

`MapData` 在现有字段末尾增加完整文本索引和关系索引，默认都是空索引，保持旧位置参数和现有
调用方兼容。`GameObject.field_values`、`references`、`referenced_by`、旧配方入口及 DOO 扁平
掉落读取方式继续可用；它们是兼容视图，不再作为新 GUI/TSV 的唯一数据源。索引内不得保存
归档、客户端数据源、Tk 控件或可变 `GameObject` 引用，只保存构建时拍平的不可变值。

### 完整文本证据模型

新增不可变的对象文本证据与解析结果，不再把 `GameObject.field_values` 中一个胜出的
`display:description` 当成全部说明。现有 `GameObject` 字段继续作为兼容视图；完整证据按地图
保存在新索引中，GUI、批量导出和知识包统一查询该索引。

每条文本证据至少包含：

- 对象分类、对象 ID、基础 ID、对象名称和是否自定义。
- 文本角色、原始字段键、原始字段标签和等级/变体序号。
- 原始完整值、可读完整值、来源种类、来源路径和来源优先级。
- 最终状态、是否占位、冲突组以及用于稳定排序的证据序号。

文本角色覆盖所有已识别的名称、称谓、编辑器后缀、短提示、扩展提示、学习提示、学习扩展
提示、启用/关闭提示、Buff/效果提示、复活提示、唤醒提示和编辑器描述。带等级或数组下标的
字段逐级保留，不能只取一级，也不能只保留最长的一项。未知但由字段元数据确认是文本说明的
字段以原始字段名导出，不因尚无中文角色名而丢弃。

原始值保留 Warcraft 颜色码、`|n`、制表符、换行、引号和空白；可读值只执行既有、确定性的
颜色码清理与换行展开。两个值分别存储，清理结果不得反向覆盖原始值。GUI 的可读区和原始区、
TSV 单元格及复制操作都输出完整字符串，不使用字符切片、摘要或省略号。

### 描述补全与状态规则

同一对象、角色和等级按以下优先级解析：

1. 地图明确提供的非占位文本。
2. 当前可用客户端数据中的对应基础对象文本。
3. 经过严格校验、键和值均唯一的可信描述缓存。
4. 没有可靠值时只保留状态，不生成替代文案。

地图中实际存在的零长度值属于“作者明确清空”，会阻止低优先级补全。固定占位集合中的
空白、`-`、`_`、`,`、`""` 和 `''` 仍作为原始证据保留，但不计作有效说明；它们属于“作者
未定义”，允许使用可靠的客户端或缓存值补缺。固定集合之外的标点和短文本不得凭长度判断为
占位。

最终状态固定为：

- `地图原值`：地图提供唯一、非占位的完整值。
- `客户端补全`：地图未定义，当前客户端提供唯一值。
- `可信缓存补全`：地图和当前客户端均未提供，校验缓存提供唯一值。
- `作者明确清空`：地图字段实际存在且值为零长度；不以低优先级来源覆盖。
- `作者未定义`：地图没有该角色，或只提供固定占位；可用来源也没有可靠值。
- `来源不可用`：地图未定义，且完成该角色审计所需的客户端或缓存无法读取。
- `来源冲突`：同一优先级存在不同非占位值；保留全部变体，不静默选一个冒充确定结果。

可信描述缓存只从工具自己发布、带所有权标记且 schema 可识别的旧结果构建。只接纳原状态为
`客户端补全`、键完全一致、原始值非占位且同键唯一的记录；冲突键不进入补全表并写入冲突
报告。缓存记录保留原发布地图 SHA-256 与来源列，状态始终显示为“可信缓存补全”。当前客户端
数据一旦可用，其结果优先于缓存。缓存不能覆盖地图原值或作者明确清空。

### 统一关系索引

新增不可变的关系记录与双向索引。每条记录有稳定关系 ID，并至少包含：

- 关系类型：怪物直接掉落、可破坏物掉落、商店出售、商店制造、合成、地面预放置、预放置
  背包、脚本/触发奖励、装备技能或共享冷却技能。
- 来源对象的分类、ID、名称；目标物品或技能的分类、ID、名称。
- 可选实例序号、所属玩家、X/Y/Z 坐标和地图子图身份。
- 可选掉落组序号、组内序号、原始概率整数、配方材料及数量。
- 证据文件、二进制记录序号/偏移或脚本函数/行号、原始证据摘要。
- 可信度、完整性状态和未解析原因。

索引提供按来源对象、目标物品、目标技能和关系类型查询的只读接口。不同实例、不同掉落组、
不同证据位置不能只因源和目标 ID 相同而合并；完全相同证据产生的重复记录按稳定关系 ID 去重。

可信度固定为：

- `已确认`：二进制实例、明确对象字段或带固定物品码参数的直接调用能证明关系。
- `可推断`：物品关系明确，但事件、接收者或来源怪物只能通过同一函数/触发上下文关联。
- `仅线索`：只知道对象码和脚本位置，不能可靠说明获取条件。

完整性固定为 `完整`、`部分`、`未解析` 或 `冲突`。UI 和 TSV 必须同时显示可信度与完整性，
不能把“可推断”或“仅线索”写成确定掉落。

## 关系来源与解析规则

### 单位与可破坏物掉落

`war3mapUnits.doo` 和 `war3map.doo` 解析器保留每个掉落集合及组内条目。单位实例新增掉落集合；
可破坏物不再只保存扁平列表。每个条目保留原始物品 ID、概率整数、集合序号、组内序号和记录
位置。现有调用方需要扁平列表时使用兼容只读视图，不能反向丢失新结构。

概率按文件中的原始整数显示为百分比，不重新归一化，也不猜测不同集合之间的运行时选择规则。
文件被容错解析为部分结果时，已恢复关系照常发布，但标为“部分”并关联组件诊断。

### 商店与位置

单位对象的 `Sellitems` 和 `Makeitems` 分别生成“商店出售”和“商店制造”关系。再按单位类型
关联 `war3mapUnits.doo` 中所有预放置实例，为每个实例保留玩家和坐标。没有预放置实例时仍保留
类型级关系，位置明确写“未预放置/可能由脚本创建”，不能伪造坐标。

### 预放置物品与背包

`war3mapUnits.doo` 中类型可解析为物品的顶层实例生成“地面预放置”关系。单位初始物品栏生成
“预放置背包”关系，保留单位实例、玩家、坐标和槽位；它与死亡掉落不是同一种关系，GUI 不以
“怪物必掉”展示。

### 合成配方

保留现有按函数识别移除材料、添加成品的规则，同时为配方增加源脚本、函数、成品调用行号、
材料及数量和可信度。标准、同一函数内可闭合的固定码写法标为“已确认”；跨函数、变量传递或
无法闭合的结果最多标为“可推断/仅线索”。去重键包含来源位置，两个不同触发中的相同配方仍
保留两份证据。

### 脚本与触发奖励

从现有脚本调用、函数、对象码和触发注册索引识别固定物品码的 `CreateItem`、
`UnitAddItemById` 及已知等价调用。关系保留接收者/坐标表达式、函数、行号和可关联的触发事件。
只有当死亡事件、触发单位和奖励调用能被同一条可验证的数据流连接时，才标为怪物相关奖励；
否则统一显示为“脚本/触发奖励”，并降低可信度。注释、字符串字面量和未执行声明不能生成关系。

WTG ECA 中可直接解析的固定物品参数也进入同一索引，证据位置使用触发器、ECA 序号和二进制
偏移。脚本与 WTG 指向同一编译结果时仅在证据完全等价时去重；无法证明等价时两条都保留并
标注来源。

### 装备技能

物品对象的 `abilList` 生成“装备技能”关系，`cooldownID` 生成“共享冷却技能”关系。技能名称
从对象索引或基础名称表解析；无法解析时仍保留原始技能 ID。装备详情显示技能的所有完整文本
角色与等级，而不是只显示一个摘要说明。

## GUI 设计

### 对象详情页

对象详情继续使用可滚动面板，并新增统一的完整文本区：先显示每个角色/等级的可读全文，再显示
对应原始全文、来源和状态。冲突时逐个列出全部变体。现有全部对象字段和引用仍保留，不因新说明
区而隐藏。

- 单位、怪物、商店或可破坏物详情增加“掉落/可获取装备”，按关系类型和实例分组。
- 物品详情增加“获取方式”和“装备技能”，列出概率、材料、玩家、坐标、证据和可信度。
- 技能详情增加“由哪些装备提供”，使用同一反向索引。
- 关系条目显示完整名称与原始 ID；未知名称明确显示“未解析”，不能只留空白。

### 独立“掉落/获取关系”页

主标签栏新增“掉落/获取”页。页面包含搜索框、关系类型筛选、可信度筛选、结果表和证据详情区。
搜索覆盖物品/技能/来源名称、ID、坐标、函数和触发名称。结果表至少包含：装备、获取方式、来源、
概率或材料、位置、可信度、完整性和证据位置。

表格不使用预览条数限制。双击一行默认打开目标装备；装备技能行默认打开目标技能。证据详情区
另有“查看来源对象”和“查看目标对象”按钮，分别切换到对象编辑器并打开对应对象详情。对象尚未
解析时按钮禁用，详情保留原始 ID 和“未解析”状态。筛选只影响当前显示，不改变底层关系或导出
结果。

## TSV 与知识包产物

每张批量地图和单图知识包新增：

- `掉落与获取关系.tsv`：一行一条获取关系，包含全部来源、实例、概率、配方、位置、证据、
  可信度和完整性列。
- `装备技能关系.tsv`：一行一条装备到技能关系，含关系角色、来源和解析状态。
- `关系完整性.txt`：按来源通道统计已确认、可推断、线索、部分和未解析数量，并列出不可用通道。

`掉落与获取关系.tsv` 的固定列为：

```text
关系ID  地图子图  关系类型  装备ID  装备名称  来源分类  来源ID  来源名称  实例序号  玩家
X  Y  Z  掉落组  组内序号  概率  槽位  合成材料ID  合成材料名称与数量  证据文件  证据函数/触发
证据行号/偏移  原始证据  可信度  完整性  未解析原因
```

`装备技能关系.tsv` 的固定列为：

```text
关系ID  装备ID  装备名称  关系角色  技能ID  技能名称  字段键  字段来源  可信度  完整性  未解析原因
```

批量 `对象描述.tsv` 升级为完整文本 schema：一行对应一个对象、文本角色、等级和证据变体，
包含原始值、可读值、来源、状态、占位标志和冲突组。知识包新增同口径的 `对象完整描述.tsv`；
现有 `对象文本与图标.tsv` 和 `对象字段.tsv` 继续保留作为兼容调查表。批量 schema 版本递增，旧
断点结果不会被误当成新格式完成结果。

完整描述 TSV 的固定列为：

```text
分类  对象ID  基础ID  名称  自定义  文本角色  字段键  字段标签  等级/变体  原始全文  可读全文
来源类型  来源路径  状态  占位  冲突组  证据序号
```

所有 TSV 使用现有标准制表符引用器。嵌入的制表符、CR/LF、引号和开头引号必须能由 Python
`csv`、Excel 等标准 TSV 读取器还原。任何列都不设置字符上限；原始字符串的导出后反解析值
必须与内存证据逐字相同。

## 数据流

```text
只读地图/战役
  -> 对象候选与全部文本字段证据
       -> 地图值 / 当前客户端 / 可信缓存解析
       -> 完整文本索引 ------------------------+
  -> DOO 掉落组、实例、背包和坐标 -----------+
  -> 对象引用（商店、物品技能）--------------+-> 统一关系索引
  -> 配方、脚本调用、触发注册与 WTG ECA ------+
                                                |
             +----------------------------------+
             -> 对象详情页
             -> 独立掉落/获取页
             -> 批量 TSV 与知识包 TSV
```

解析和索引构建只发生一次。`MapData` 关闭时继续释放归档资源；文本和关系索引只保留不可变的
普通 Python 值，不持有 MPQ、客户端数据源或图片句柄。

## 错误、冲突与安全处理

- 客户端目录不存在或不完整时标记“来源不可用”，不能等价为“作者未定义”。
- 可信缓存损坏、schema 不匹配、来源标记缺失或同键冲突时不采用该键，并写入稳定诊断。
- 未知物品或技能 ID 仍发布关系证据；名称写“未解析”，不会删除整条关系。
- 单个 DOO 记录、脚本函数或 WTG ECA 解析失败只降低对应通道完整性，不抹掉其他已恢复关系。
- 同优先级文本冲突保留全部原值；关系证据冲突保留各条并标为“冲突”。
- 单个 TSV 写入失败沿用安全写入与原子发布边界，不留下可被断点续跑误认的完成目录。
- 处理前后复核源地图大小和 SHA-256；所有读取路径继续拒绝执行载荷、符号链接逃逸和输出穿越。

## 测试策略

### 单元与集成测试

## 验收标准

- 所有可读取来源中的文本证据保留率为 100%，原始值 TSV 往返后逐字一致。
- 每个已识别文本角色和等级均可在对象详情与 TSV 中找到；任何界面不使用摘要替代全文。
- 没有可靠文本时显示准确状态，不生成或拼接虚构说明。
- 单位和可破坏物的掉落组、组内条目与概率不再丢失或扁平化。
- 怪物可查掉落装备，装备可反查全部已证明获取方式与技能，技能可反查提供它的装备。
- 独立关系页和 TSV 与对象详情使用同一索引，筛选前后的底层记录数不变。
- 39 张源地图处理前后大小与 SHA-256 完全不变。

## 已知静态边界

- 动态变量计算、随机池运行时变更、跨脚本间接调用和混淆逻辑可能只能形成线索，不能保证还原
  实际游戏中的每一次奖励。
- 缺少客户端数据且可信缓存没有对应键时，只能标记“来源不可用/作者未定义”，不能凭经验补文。
- 掉落概率保留编辑器原始整数；没有足够格式证据时不推导多组之间的最终联合概率。
- “完整”表示所有可读取静态证据均已保留和准确标记，不表示工具运行了地图并验证动态行为。
