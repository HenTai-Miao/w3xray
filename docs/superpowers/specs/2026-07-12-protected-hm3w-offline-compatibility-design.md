# 设计：受保护 HM3W 地图的纯离线 StormLib 兼容

- 日期：2026-07-12
- 状态：用户已批准；实现后的安全审查加固已记录
- 参考程序：`魔兽多功能存档盒子1.8.0.9`
- 目标项目：`w3xray`

## 已确认事实

参考程序有两条入口：游戏内入口先取得并复制当前地图，纯离线入口直接打开用户选择的磁盘地图；两者最终调用同一个 StormLib 对象解析器。纯离线入口不检查 `Game.dll`，依次读取 `war3map.wts`、`war3map.w3t`、`war3map.w3u`、`war3map.w3a` 和 `war3map.w3q`。

两张失败地图的根因均在 MPQ 布局兼容层：

- `A80167E5296276AD606B310D4B54F61F.w3x` 的 MPQ 头位于 `0x200`，原始 `header_size=0xCA30467C`，但 hash/block 表和 23 个 live block 均有效，五类离线对象文件全部存在。
- `A8E238ED8C50ECB52657B7265B01D4BA.w3x` 的 MPQ 头位于 `0xA00`，原始 `header_size` 字节为 `PACK`；hash/block 表偏移需要按 32 位无符号加法回绕，表实际连续位于主头之前。

旧盒子离线读取前会用 `LB_RESETCONTENT` 清空四类 UI 列表。报告写入使用 `CREATE_ALWAYS`，但物品列表为空时会在写任何文件前直接返回。因此 A8E 可以开档成功，而旧的 `提取的ID/*.txt` 仍留在磁盘；旧文件不是本次地图产生的对象证据。

## 目标

- 在纯 Python 解析器中复刻这两张图所需的 StormLib 9.25 经典 MPQ 布局语义。
- A801 能完整读取标准地图文件并进入现有对象解析链。
- A8E 能读取其真实外层 MPQ 内容和地图信息，不再因保护头直接开档失败。
- 开档异常时立即释放 mmap、文件句柄和临时副本。
- 实际解析器与有界诊断对同一布局给出一致结论。
- 保持只读、跨平台和现有公开 API 兼容。

## 非目标

- 不执行旧 EXE、DLL、地图脚本、loader 或匿名载荷。
- 不注入游戏、不读取运行内存、不绕过反作弊。
- 不猜测解密 A8E 的 228,883,105 字节 KKWE 尾部；该尾部不属于六项 MPQ block 表。
- 不伪造 A8E 缺失的 WTS 或四类二进制对象文件，也不把旧报告当成新结果。
- 不把 Windows `StormLib.dll` 引入为运行时依赖。

## 方案选择

采用纯 Python 复刻 StormLib 9.25 的已确认布局行为。Windows DLL 回退不能提升 A8E 的对象恢复能力，并会引入平台、ABI、打包和资源生命周期问题；直接逆向 KKWE 尾部则没有参考程序离线链证据支持。

## MPQ 布局规则

“经典格式”在本设计中明确指 MPQ 头字段 `format_version == 0`；StormLib 源码中有时称其为第一版头，二者不是不同格式。

仅当文件以 Warcraft III `HM3W` 魔数开头且候选主头为经典格式时启用保护图规则：

1. 原始 `header_size` 仍必须至少为 32 字节。
2. 超出文件范围的原始头大小只作为 malformed 诊断证据，解析使用固定的 32 字节有效头；不得按垃圾值分配、读取或切片。
3. hash/block 表绝对位置按 `(archive_offset + stored_offset) & 0xFFFFFFFF` 计算，与 StormLib 的 DWORD 加法一致。
4. hash 数量仍须为正的 2 次幂，完整 hash 表必须位于文件内。
5. block 表起点必须位于文件内；沿用现有 StormLib 兼容行为，只读取实际存在的完整 16 字节表项。
6. 后续 block 索引、压缩大小、文件大小、扇区偏移和解压预算继续使用现有严格边界检查。
7. 非 `HM3W`、非经典格式、头小于 32 字节、回绕后仍越界的输入继续拒绝。
8. UserData 包装仍为权威入口，现有合法标准 MPQ 行为不得改变。
9. 普通对齐扫描只检查文件前 16 MiB，偏移 0 的合法 UserData 仍可直接指向其声明的主头；这限制无头稀疏文件的 CPU 消耗，同时覆盖当前 27 张图已观测到的最大主头偏移 2560。
10. hash 表和文件内实际可读的 block 表各最多物化 262,144 项；block_count 注水但文件内实际项较少时继续按 StormLib 兼容方式截断，不因声明尾部越界而拒绝。当前 27 张图最大值分别为 8192 和 5316。

保护布局只改变只读定位语义，不提供写回能力。任何 malformed 地图在本项目中始终只读。

## 资源生命周期

`w3xtool/mpq.py` 已达到 250 行纯代码，不能继续叠加文件和 mmap 生命周期逻辑。新增单一职责的 backing-store 模块，负责：

- 打开原始文件；大文件使用只读 mmap，小文件读入内存后立即关句柄。
- 通过非阻塞描述符只打开一次，再由 `fstat` 确认普通文件；小文件最多读取该描述符报告的大小，避免无写端 FIFO 卡死、设备文件和路径替换造成无界读取。
- 原始文件因权限或占用无法直接打开时，创建受控临时副本。
- 初始化任一步骤失败时关闭 mmap 和文件，并删除临时副本。
- `close()` 可重复调用，成功构造后的上下文管理行为保持不变。

`MPQArchive` 继续暴露现有 `_data` 兼容表面，读取、导出和身份计算调用方不需要迁移；资源所有权由 backing store 集中管理。

## 诊断

`archive_diagnostics` 继续只做对齐的 32 字节有界读取，不扫描或加载载荷。纯候选布局验证位于 `archive_layout_probe`，复用相同的头大小、表偏移和表物化预算，并保留：候选偏移、原始头大小、格式版本、表范围及是否使用保护图归一化。可兼容的 A801/A8E 不再误报为表损坏；真正越界和不支持版本仍保持原分类。

## 用户可见语义

- A801：开档成功，标准对象文件、脚本和现有资料包流程照常工作。
- A8E：开档成功，显示地图《轮回世界》及外层真实文件；标准对象源缺失时结果为 0 个地图对象，现有对象来源/需求覆盖报告明确显示“未发现”，而不是显示开档异常或沿用旧 ID。
- 所有地图源文件保持字节不变。

## 测试设计

### 红灯单元与集成测试

- `HM3W + format_version=0` 的垃圾大头可归一化并读取真实成员。
- 两张表位于主头之前时，32 位回绕可读取真实成员。
- 同一保护布局在有界诊断中归类为结构可兼容。
- 非 `HM3W` 的垃圾大头仍拒绝。
- 非经典版本不启用兼容。
- 原始头小于 32 字节仍拒绝。
- 单表伪回绕、回绕后表越界、非法 hash 数量仍拒绝。
- 现有标准头、UserData、诱饵头和截断 block 表测试全部保持通过。
- 大文件解析头失败时，真实文件句柄和 mmap 均已关闭。
- 临时副本路径解析失败时，句柄关闭且副本删除。
- `close()` 成功路径仍可重复调用。
- FIFO/设备等非普通文件在读取前拒绝，路径大小不在打开前单独查询。
- 意外 mmap 异常仍关闭源句柄；临时副本清理失败不得遮蔽原始开档异常。
- 主头超过 16 MiB 搜索预算以及可物化表超过 262,144 项时立即拒绝。

## 安全边界

整个实现只读取用户提供的地图字节；不执行任何来自旧软件或地图的代码。对保护头的兼容不能放宽 block、扇区、解压输出和导出路径的既有安全限制。
