## 目标

1. 删除非图标字段造成的假引用，并使每个未解析图标都有逐行、可搜索、可复算的原因和来源。
2. 修复文本角色身份与来源优先级，使真正冲突只表示同字段、同等级、同优先级的不同正文。
3. 在不修改历史目录的前提下，从现有历史客户端证据重建一个新的、来源清单绑定的可信描述缓存。
4. 将发布、档案完整性和知识证据完整性拆开，避免把成功发布和静态证据缺口混成一个状态。
5. 使用 schema 5 在新输出根完整重跑 39 张地图，并证明源地图和历史输出均未改变。

- `/Users/zhongerbing/Desktop/Maps` 始终只读。

  `map-extract-output-v5` 和显式指定的工具自有缓存目录。

## 总体结构

系统增加两个不可变索引：图标证据索引和文本选择索引。GUI、每图报告、全局报告和批处理状态
共同消费这些索引，不在展示层重新推断。

图标索引同时保存已解析记录、过滤记录、未解析记录和候选记录。文本索引同时保存当前值和全部
来源变体，每条变体携带优先级与选择理由。批处理状态从两个索引和档案账本派生，不根据报告文本
反向计算。

## 图标证据模型

### 引用证据

每个有效图标引用至少保存：

- 地图路径、地图 SHA-256 和战役子地图身份；
- 对象分类、rawcode、名称和基础 rawcode；
- 字段键、字段标签、字段类型、字段来源和 WTS 来源；
- 原始路径、规范路径及按顺序尝试的候选路径；
- 当前地图、战役根、同地图历史证据和可信缓存的查询结果。

引用收集不得只依赖已经折叠的 `GameObject.icon`。对象物化必须保留被选中图标字段的精确证据，
图标收集器从该证据建立不可变引用。

### 字段资格

以下字段可直接作为已知图标语义：

- 单位 `uico`；
- 物品 `iico`；
- 技能 `aart` 以及可信技能文本表中的 `Art`；
- 科技 `gar1`；
- Buff/效果 `fart`；
- 字段元数据明确为 `icon` 且分类上下文一致的等价字段。

`w3d:dfil`、`w3b:bgsc`、类型为 `model`、`real` 或其他非图标类型的字段不得进入图标解析。
它们进入“已过滤非图标字段”审计计数，但不计为未解析图标。

### 路径规范化与查询

只执行可逆且确定的规范化：

1. 保留原始值；
2. 清理外围空白和一层配对引号；
3. 将 `/` 统一为 `\`，去除没有语义的根分隔符；
4. 按原路径、同基名 `.blp`、`.tga`、`.dds` 的固定顺序查询；
5. 对已知 Warcraft 客户端命名空间执行明确的前缀规范化。

禁止把 basename、最短后缀、大小写以外的模糊匹配当作解析成功。目录数据源现有的 basename 回退
不得用于证据级图标解析；若为了浏览功能保留该行为，证据解析必须使用严格查询接口。

解析优先级固定为：

1. 当前地图或当前战役子地图；
2. 战役根地图；
3. 显式提供且验证可读的真实客户端目录；
4. 与当前源地图 SHA-256 绑定的历史图标证据；
5. 可信客户端图标缓存。

当前本机没有真实客户端，因此 revision 5 的本地验收从第 4 项继续。以后重新提供客户端时，
真实客户端优先于历史缓存，且依赖指纹必须随客户端证据变化。

每次成功解析都记录真实来源路径、解析路径、内容 SHA-256 和所有引用对象。

### 未解析原因

未解析记录使用枚举原因和补充诊断，不使用自由文本作为唯一判断依据。原因至少覆盖：

- `invalid_reference`：路径为空、格式不合法或不是支持的图片引用；
- `named_resource_missing`：所有严格具名来源均不存在该路径；
- `anonymous_payload_unbound`：地图存在匿名图片载荷，但没有名称到块的静态绑定；
- `client_source_unavailable`：需要客户端证据但当前未提供完整客户端源；
- `historical_client_miss`：同地图历史真实客户端运行也没有该解析证据；
- `archive_name_unavailable`：档案名称表或哈希证据不可用；
- `archive_block_damaged`：相关档案存在损坏块，无法证明具名载荷；
- `filtered_non_icon_field`：原字段不是图标；该原因只进入过滤统计。

一个记录可保留多个诊断标志，但必须有一个稳定的主原因。原因选择顺序由模型层固定并由测试锁定。

### 图标产物

每图增加 `图标未解析.tsv`，全局增加：

- `图标缺口汇总.tsv`；
- `图标候选绑定.tsv`；
- 按原因、前缀、扩展名、对象分类和地图聚合的 `图标缺口统计.txt`。

`图标未解析.tsv` 每行对应一个地图内去重路径及其完整引用集合。全局汇总必须能逐行回算每图计数
和批量总数。候选绑定明确标记“未采用”，不能减少未解析计数。

`图标完整性.txt` 分开显示有效引用、已解析、已过滤、具名未解析、匿名载荷、原始写出失败、PNG
失败和受限/损坏档案，不再把这些数量合并为一个“失败”。

## 完整文本证据模型

### 精确文本角色

自然语言正文角色只按明确字段身份或可信元数据标签识别：

- `Tip/utip/atp1`：基础提示；
- `Ubertip/utub/aub1`：扩展提示；
- `Researchtip/aret`：学习提示；
- `Researchubertip/arut`：学习扩展提示；
- `Untip/aut1`：关闭提示；
- `Unubertip/auu1`：关闭扩展提示；
- Buff 的 `Tip/ftip` 与 `Ubertip/fube`：Buff 提示与 Buff 扩展提示；
- 名称、称谓、编辑器后缀、复活、唤醒和编辑器描述继续使用现有明确键表。

标签回退必须匹配完整语义标签，不能因为包含 `research`、`off`、`close` 或 `uber` 子串就归入
正文角色。`ResearchArt`、`Researchbuttonpos`、`Researchhotkey`、`Orderoff` 等保留自身字段身份。
元数据明确为字符串但未命中正文角色的字段，以规范后的原始字段键作为角色；非字符串控制字段不
作为描述正文。

### 身份、优先级和选择

文本身份由分类、对象 ID、规范语义字段、角色和等级/变体组成。WTS 是值来源位置，不是独立的
优先级层。

来源优先级沿用对象物化语义：

1. 地图文本字符串；
2. 地图二进制；
3. 地图函数文本；
4. 地图 SLK；
5. 地图匿名文本块；
6. Warcraft 客户端；
7. 可信描述缓存。

每个 `TextEvidence` 增加规范字段身份和来源优先级。解析器先选择最高可用优先级：

- 该级只有一个非占位原值时，它是当前值；
- 该级同一字段存在多个不同非占位原值时，全部标记 `来源冲突`；
- 低优先级原文继续完整保留，但 `是否当前值=否`，选择原因为 `低优先级证据`；
- 地图明确零长度值继续阻止客户端和缓存补全；
- 固定占位值作为 `作者未定义` 证据保留，但允许低优先级可信值成为当前值。

七种既有状态保持不变：地图原值、客户端补全、可信缓存补全、作者明确清空、作者未定义、
源数据不可用、来源冲突。新增的“是否当前值、证据优先级、选择原因”是正交列，不增加一个含混的
状态。

### 原文与展示

所有证据继续保存不截断的原始全文和只去除 Warcraft 颜色代码、展开换行的可读全文。TSV、GUI
和复制功能不得截取预览值替代正文。`对象完整描述.tsv` 增加：

- 规范字段身份；
- 证据优先级；
- 是否当前值；
- 选择原因。

冲突组只在真正同级冲突时非空。低优先级不同值不再生成冲突组。

## 历史可信描述缓存重建

### 显式迁移

新增独立命令：

```text
uv run main.py description-cache migrate \
  --legacy-output <schema-1-output-root> \
  --legacy-cache <schema-2-cache-tsv> \
  --output <owned-trusted-cache-root>
```

命令不自动搜索历史目录，不硬编码用户路径。输入只读，输出根必须由工具新建或持有正确所有权
标记。结构损坏、符号链接逃逸或来源根重叠时预检失败。

### 单行接受条件

一个候选只有同时满足以下条件才进入新缓存：

1. 分类、基础 ID、角色和等级语法合法，且是原版基础对象身份；
2. 候选来源地图 SHA-256 存在于 schema 1 批量状态；
3. 来源路径严格位于显式 legacy output 根内；
4. 来源 `对象描述.tsv` 中存在字段逐字一致的 `客户端补全` 行；
5. 来源标识为 `base:<同一基础ID>`，不是自定义对象或其他地图自定义说明；
6. 原始全文与可读全文通过当前可读转换和 TSV 往返校验；
7. 同一分类、基础 ID、角色和等级在全部候选中只有一个原始值；
8. 来源文件、批量状态和候选缓存均被哈希并写入新来源清单。

不满足条件的候选写入 `可信缓存迁移拒绝.tsv`，包含稳定原因码，不参与补全。迁移允许部分接受，
但结构级错误必须整体失败。

### 新缓存格式

缓存目录包含：

- `.w3xray-trusted-description-cache` 所有权与 schema 标记；
- `可信描述缓存.tsv`；
- `来源清单.tsv`；
- `可信缓存迁移拒绝.tsv`；
- 内容清单及整体 SHA-256。

批处理新增显式 `--description-cache <cache-root>` 参数。每次打开都重新验证标记、清单、来源行摘要
和内容哈希。缓存清单哈希进入批处理依赖指纹。没有通过验证时批处理预检失败，不能静默降级。

现有 v2 的 3,043 条记录只是候选上限，不预设全部接受。迁移报告给出接受、拒绝和各原因数量。
历史数据没有覆盖的文本角色继续标记 `源数据不可用`。

## 三轴状态

schema 5 为每张地图保存三类正交状态。

### 发布结果

- `已发布`：原子发布和必需产物校验成功；
- `失败`：地图级结构、处理或发布失败；
- `取消`：用户或运行时取消。

### 档案完整性

- `完整`；
- `存在原始块`；
- `存在损坏块`；
- `存在受限块`。

该轴只从提取账本和载荷写出结果派生。

### 知识证据完整性

聚合状态为 `完整` 或 `部分`，同时保存一个或多个原因标志：

- 缺少客户端；
- 图标未绑定；
- 关系部分；
- 真正来源冲突；
- 端点未解析。

既有 `MapBatchState` 作为兼容组合值保留一个 schema 周期，但不再作为 GUI 和全局汇总的首要
状态。schema 5 权威报告首先显示发布结果，然后分别显示档案和知识证据状态。旧 schema 4 结果
不得被 revision 5 断点复用。

## GUI

GUI 总览增加三轴状态列和对应计数。对象详情显示：

- 已解析图标的真实来源、解析路径和 SHA-256；
- 未解析图标的主原因、诊断和引用字段；
- 当前文本值及其选择理由；
- 可切换的全部文本证据、低优先级值和真正冲突。

新增“图标缺口”工作区，支持按地图、原因、对象分类、rawcode、路径和档案状态搜索。双击记录打开
对应对象。候选绑定使用单独筛选和醒目标记，不能通过 GUI 操作直接提升为已解析。

所有完整正文使用可滚动控件并支持复制全文。GUI 后台任务继续使用现有有界 worker 和 Tk 主线程
回调，不在界面线程重载地图。

## 错误处理

- 预期的文件不存在、路径不命中和匿名块无绑定形成结构化未解析记录，不抛弃整张地图。
- 图标读取、解码或写出错误分别计数，不能用“未解析路径”替代写出错误。
- 单个分析通道的未预期异常继续由现有地图级故障隔离记录诊断，其他通道照常发布。
- 显式提供的可信缓存结构或哈希错误属于启动预检失败，不能当作普通缓存未命中。
- 所有错误报告必须使用稳定原因码并附带人类可读详情。
