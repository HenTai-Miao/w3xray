# 设计：批量图标与对象描述完整提取

## 背景

目标地图目录为：

`/Volumes/zhongerbing/Program Files (x86)/Warcraft III/Warcraft III Frozen Throne/Maps/`

目录中现有 37 张 `.w3x` 地图，总大小约 4.1 GiB，最大单图约 496.5 MiB。
37 张地图均可通过轻量探测读取显示名，但抽查发现受保护地图会删除或隐藏内部文件名，
导致普通按路径查找不能覆盖所有自定义图标。最大样本中可恢复 4324 个匿名 BLP，
对象引用的 1333 个唯一图标路径中仅 770 个能按路径直接解析，另有 563 个不能证明路径对应关系。

对象描述也存在来源缺口。最大样本的 4141 个对象中，单位、物品和科技描述覆盖较高，
但技能仅 11/460 有完整说明。相邻游戏目录包含 `war3.mpq`、`War3x.mpq` 和
`War3Patch.mpq`，当前客户端数据源没有把这些经典 MPQ 作为对象文本来源，
因此无法用官方基础对象文本补齐地图未覆盖的名称、提示、描述和图标。

## 目标

- 递归处理目标目录中的全部 `.w3x`、`.w3m` 和 `.w3n` 文件。
- 每张地图同时导出原始 BLP 和可直接查看的 PNG。
- 对具名图标保留对象分类、对象 ID、对象名称、原始路径和真实来源。
- 对匿名 BLP 使用块编号和内容哈希命名，不猜测原始文件名或对象关联。
- 为每个对象导出原始描述、可读描述、短提示、字段来源和完整性状态。
- 从经典 MPQ 补齐基础对象文本，但不得覆盖地图明确设置或明确清空的字段。
- 支持中断续跑、失败隔离、逐图重试和全局汇总。
- 地图目录始终只读；所有结果写入项目仓库外的独立输出目录。

## 非目标

- 不执行地图、历史 EXE、DLL 或地图脚本。
- 不进行进程内存读取、注入、运行时解密或保护绕过。
- 不为匿名图标推测未经证明的原始路径。
- 不自动编造地图或客户端数据中不存在的描述。
- 不并行加载多张超大地图。

## 方案选择

采用在现有提取器上增加可恢复批量工作流的方案。该方案复用现有 MPQ、对象管线、
提取证据和安全写入边界，同时新增经典 MPQ 客户端数据源、专用图标发布器、描述审计器
与批量调度器。

未采用仅批量解包 BLP 的方案，因为它不能解决对象关联和描述缺口；也不采用匿名路径
推测方案，因为无法证明结果正确。

## 架构

### 经典 MPQ 数据源

新增只读经典 MPQ 数据源，按以下优先级查找内部文件：

1. `War3Patch.mpq`
2. `War3xLocal.mpq`（存在时）
3. `War3x.mpq`
4. `war3.mpq`

经典安装目录必须在普通散文件目录探测之前识别，避免把只包含 MPQ 容器的目录误判为
已导出的散文件目录。数据源实现现有 `GameDataSource` 协议，为对象文本、TriggerData 和
图标提供统一的 `has_file`、`read_file` 与 `close` 能力。

地图对象字段的优先级保持：地图明确值或明确空值 > 客户端基础对象值 > 内置快照。
客户端数据只能补缺，不能覆盖地图作者的取值。

### 批量调度器

新增目录批处理入口，递归扫描地图扩展名并按稳定顺序逐张处理。默认一次只加载一张地图，
每张地图完成后立即关闭 archive、客户端数据源和图片对象。

调度器为每张地图记录源路径、大小、修改时间、SHA-256、输出目录、阶段、最终状态和首个
错误。中断恢复时，大小、修改时间和 SHA-256 均未变化且结果完整的地图直接跳过；失败、
部分完成或已变化的地图重新处理。

### 图标提取器

图标来源分为两条互补通道：

- 具名/引用通道：收集所有对象图标路径，按地图、战役外层、经典客户端数据的顺序读取。
  同一规范化路径只导出一次，索引中保留引用该图标的全部对象。
- 匿名块通道：消费提取证据中所有已恢复且识别为 BLP 的匿名块。每个块只读取一次，原始
  文件命名为 `block_六位编号_SHA前8位.blp`，PNG 使用相同基名。

原始 BLP 必须先安全写出，再尝试 PNG 转换。PNG 解码失败时保留原始 BLP 并记录失败，
不得把整张地图判为完全失败。批处理不使用会长期缓存所有 PIL 图片的 GUI 图标缓存；每张
图片完成后立即释放。

### 描述审计器

每个最终对象必须产生一条描述审计记录。记录包含：

- 分类、对象 ID、基础 ID、对象名称。
- 短提示、原始完整描述、清理后的可读描述。
- 提示来源、描述来源和对象是否自定义。
- `地图原值`、`客户端补全`、`地图明确清空` 或 `源数据缺失` 状态。

原始列保留 Warcraft 颜色码、`|n` 和其他原始标记；可读列使用既有文本清理规则移除颜色码
并展开换行。缺失描述不得自动生成替代文本。

## 输出结构

默认输出根目录为：

`/Users/zhongerbing/Documents/xm/war3_xg/map-extract-output/`

```text
map-extract-output/
├── 批量提取汇总.tsv
├── 批量提取状态.json
├── 失败与重试.tsv
└── 地图/
    └── 001_地图名_SHA前8位/
        ├── 地图摘要.txt
        ├── 图标索引.tsv
        ├── 对象描述.tsv
        ├── 图标完整性.txt
        ├── 描述完整性.txt
        └── 图标/
            ├── 原始/
            │   ├── 具名/
            │   └── 匿名/
            └── PNG/
                ├── 具名/
                └── 匿名/
```

地图目录名同时包含清理后的显示名和源 SHA-256 前 8 位，避免同名地图互相覆盖。具名图标
路径必须通过现有安全相对路径规则；大小写或清理后冲突时追加内容哈希。

## 完整性状态

逐图状态定义如下：

- `完整`：容器清单没有受阻块；所有识别出的 BLP 都已写出原始文件并生成 PNG；所有对象
  都有描述审计记录，且没有 `源数据缺失` 的描述。
- `部分完成`：存在路径无法读取、BLP 无法解码、原始描述缺失、原始块只能保留等情况，
  但所有可恢复结果已发布。
- `受限`：存在缺少静态密钥的加密块或其他明确的静态提取边界。
- `失败`：地图容器无法建立可靠清单，或结果目录无法安全发布。

全局汇总必须按地图列出对象数、描述状态计数、具名图标数、匿名 BLP 数、原始写出数、
PNG 成功数、失败数、受限块数、耗时和最终状态。

## 数据流

```text
地图目录扫描
  -> 稳定地图清单
  -> 单图加载 + 提取证据
       -> 对象管线 + 经典 MPQ 补全
       -> 具名图标解析 -----------+
       -> 匿名 BLP 块恢复 --------+-> 原始 BLP -> PNG -> 图标索引
       -> 对象描述审计 -----------------------> 对象描述.tsv
  -> 临时目录完整写入
  -> 原子发布单图结果
  -> 更新断点状态和全局汇总
```

## 错误与资源处理

- 单个图标读取或解码失败只影响该图标，继续处理剩余条目。
- 单张地图失败只影响该地图，批量任务继续处理后续地图。
- 所有错误写入稳定的阶段、类型和单行消息，不隐藏首个失败原因。
- 临时目录只有在必要文件写完后才原子发布；未发布目录不能被断点状态视为成功。
- 输出文件继续使用现有安全写入边界，拒绝绝对路径、父目录、符号链接逃逸和路径冲突。
- BLP 尺寸继续受现有 4096 像素单边上限保护。
- 地图间不并行；单图匿名图标逐个转换并释放，避免图片缓存随图标数量增长。
- 地图、经典 MPQ 和图片句柄在成功与异常路径均显式关闭。

## 测试与验收

### 自动化测试

- 经典 MPQ 优先级、目录探测、关闭幂等和客户端文本读取。
- 地图明确值、地图明确空值、客户端补全和内置快照的字段优先级。
- 具名图标去重与多对象引用关系。
- 匿名 BLP 稳定命名、原始写出、PNG 转换和解码失败降级。
- 描述原始值、可读值、来源与四种状态。
- 两张合成地图中一张失败时继续处理另一张。
- 中断恢复跳过未变化的完整结果，并重试失败或变化结果。
- 输出路径穿越、符号链接和清理后重名回归测试。

### 真实地图验收

1. 使用最小地图验证基础对象补全和具名图标解析。
2. 使用最大地图验证数千匿名 BLP 的流式导出、内存边界和部分完成报告。
3. 运行全部 37 张地图，生成全局汇总并确认源地图大小、修改时间和内容未被改变。
4. 抽查原始 BLP 与 PNG 内容、对象描述原始列与可读列、匿名块编号和 SHA-256。
5. focused tests、完整 pytest、ruff 和 basedpyright 全部通过后才声明开发完成。

## 已知限制

- 删除名称哈希的匿名块只能按块编号与内容哈希导出，不能证明其原始路径或对象关联。
- 静态密钥未知的加密块只记录受限证据，不尝试运行时解密。
- 地图和客户端都没有提供的描述只能标记缺失。
- PNG 是便利副本；原始 BLP 才是保真证据。
