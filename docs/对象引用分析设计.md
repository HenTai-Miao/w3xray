# 对象引用分析（references）设计

> 来源：从「魔兽ID拖入无反应解决方法」工具包（Wc3SLKOpt / Wc3MapMax++）的
> `Config.ini [SearchObjectData]` 提取**对象引用知识**，落成本工具的**只读**分析。
> 不照搬其改图/重打包功能（与本工具只读 X 光定位不符）。

## 目标（只读，不改图）
1. **正向引用**：选中一个对象 → 它引用了哪些技能/训练单位/建造建筑/出售物品/依赖科技…（还原中文名）。
2. **反向引用**：某技能/buff/单位被哪些对象引用。
3. **孤立对象报告**：定义了、但没有任何对象/脚本/预放置引用的**自定义**对象（"死对象"）。

## 路线：混合
- **二进制对象**(w3u/w3t/w3a/w3q/w3b/w3d/w3h)：**类型驱动**——字段类型(`FIELD_TYPES[field_id]`)属于引用类则视为引用字段。覆盖自定义字段最全。
- **文本格式对象档**(textobj，键是 `abilList` 这类 SLK 列名、无 4cc 类型)：**列名驱动**——用取自优化器 `[SearchObjectData]` 的列名表。
- 两条路汇进同一份引用边列表。

### 引用类型表（实测 FIELD_TYPES 类型 → 目标分类）
| 类型 | 目标分类 |
|---|---|
| abilCode, abilityList, heroAbilityList | 技能 |
| unitCode, unitList | 单位 |
| itemList | 物品 |
| upgradeCode, upgradeList, techList | 科技 |
| buffList, effectList | 增益 |

`intList/unrealList/stringList/modelList/targetList/unitClass/…` 等**不是**对象引用（数值/字符串/枚举），排除。

### 引用列名表（文本对象，取自优化器 SearchObjectData）
- 单位：abilList, heroAbilList, Makeitems, Sellitems, Builds, Sellunits, Trains, Upgrade, Researches, upgrades, Requires, Reviveat, DependencyOr, Requires1..8
- 物品：abilList, Requires, cooldownID
- 技能：BuffID, EfctID, Requires
- 科技：Requires, code1..4

## 数据结构
- `GameObject.ref_fields: list[(field_label, [code…])]`——在 `_build_objects` 趁 `o.mods`(原始 field_id+value) 时捕获；文本对象在 `_add_text_objects` 用列名表捕获。
- `MapData.references: dict` `obj_id → [(字段标签, [(码, 名字|None)])]`（正向）
- `MapData.referenced_by: dict` `码 → [(引用者ID, 引用者名, 字段标签)]`（反向）
- `MapData.orphans: list[GameObject]` 孤立自定义对象

### 孤立判定
`o.is_custom 且 o.obj_id ∉ (被任何对象引用 ∪ 脚本引用(scan_object_refs) ∪ 预放置类型(md.units/md.doodads))`。
原版对象(`is_custom=False`)天然不计入——等价优化器 `ObjectAlwaysUsed` 保留逻辑，但更简单。

## 模块与接入
- 新模块 `w3xtool/references.py`：`REF_TYPES`、`REF_COLUMNS`、`extract_refs_by_type()`、`extract_refs_by_column()`、`build_reference_graph(md)`。纯函数、无 IO/GUI。
- `api.load_map` 末尾 `try/except` 调 `build_reference_graph(md)`（失败优雅降级，符合现有容错风格）。
- **GUI**：`_show_detail` 字段后追加「引用 →」「被引用 ←」两节（码还原 `名字(码)`）；新标签页「孤立对象」复用预放置/指令那套 Treeview+回车搜索（列：分类/ID/名称）。
- **CLI**：`cli` 子命令打印孤立数量与样例。

## 测试 `tests/test_references.py`
- `extract_refs_*`：合成 mods/字段 → 正确抽出引用码、过滤非引用类型。
- `build_reference_graph`：迷你 MapData（单位→技能边）测正向边、反向索引、孤立判定（被引用的不算孤立、原版不算孤立）。

## 不做
- 不做任何 SLK 优化/重打包/删 WE 文件/裁剪未用对象（改图功能，越界）。
- 文本对象的列名表只覆盖常见引用列；少见列漏判仅影响"孤立"误报为更多，不影响正确性（只读报告）。
