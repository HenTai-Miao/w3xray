# GameXRay 0.10.0 使用说明

本版维护 Windows x64，提供目录版 ZIP 与单文件 EXE。日常使用建议完整解压
`gamexray-v0.10.0-windows-x64.zip`，运行其中的 `GameXRay 游戏档案透视器.exe`，
保留旁边的 `_internal` 文件夹。地图、战役、参考库、知识包和存档分析都可离线使用，
无需安装 Python。实时探针需要对应的运行中游戏。

## 地图与战役的完整对象层

正常打开地图或战役即可使用新的解析逻辑，无需打开额外开关。
单位、物品、技能、科技、可破坏物、装饰物、增益同时读取普通对象文件和
`war3mapSkin.*` / `war3campaignSkin.*`。没有 `(listfile)` 的归档也会检查这些固定成员名。

同类对象的字段按战役普通层、战役 Skin 层、章节普通层、章节 Skin 层选择。
明确的空覆盖会保留；低层字段、重复内容、冲突与原始字节仍能在完整证据中查询。
Skin 与普通层共用其地图或战役的 WTS，不会到虚构的 Skin WTS 文件中找名字。
不同章节、不同类别中的同码对象仍各自独立。

v3 对象头按“额外整数数组 + 一份修改列表”读取，数组为空或含多个整数时不再漏字段。
每条字段修改保留数据列、等级/变体、原始字节区间及末尾校验值。
数据列独立于等级，多个数据列不会相互覆盖。未知类型、截断、非法数量与未消费尾部
继续保留诊断；能确认的对象和字段仍可查看，不会把部分读取标成完整。

对象详情、知识包、物品/技能/科技查询和参考目录共用这些证据。
当前值摘要与差异比较排除已被覆盖的旧值，完整详情仍保留旧值及其来源。
新知识包为已选择的八类对象写出完整表头；来源完整而无记录的类别在统计中显示为 0。
`对象来源覆盖.tsv` 保留逐类别选择状态和全部来源诊断，参考目录、对象查询与统计共同读取。
损坏或未读取的来源仍标为不完整；未选择的类别不能视为空类别。覆盖表被修改或删除后会重新核验，
旧外部包继续按其实际表与诊断读取，不借此证明原地图完整。
这一变化更新了批次提取、实时知识包和指引的缓存版本；已有导出和历史缓存文件保留。

```powershell
& '.\GameXRay 游戏档案透视器.exe' reference --map 'D:\地图\示例.w3x' --kind objects --json
& '.\GameXRay 游戏档案透视器.exe' cli 'D:\地图\战役.w3n' --pack 'D:\报告\新的战役包'
& '.\GameXRay 游戏档案透视器.exe' pack-query 'D:\报告\新的战役包' item '' --json
```

## 参考库多选、导出与查询

从「数据工具」打开参考目录，可选择地图/战役、已有知识包或外部 ID 来源。
左侧列表支持 Ctrl 多选、Shift 连选、全选和清空选择，选择数量独立显示。
复制或导出所选条目时保留每条的全部字段、原始记录、类别、章节范围和来源诊断。

选中导出提供 JSON、Markdown 和 TSV。TSV 使用可逆的单元格编码，完整记录以 JSON
单元格保存；带换行、引号、制表符和安全前缀的内容不会被截成物理行片段。
选择清单同时记录当前列表数量、匹配总量和用户明确限制产生的遗漏数量。
原有“全部匹配”导出继续可用。

选择知识包中的单个对象，可以进入该对象所属知识包或战役章节的查询窗口。
跳转按类别选择查询模式，并核对记录来源；不会借用主窗口中另一张地图的知识包。
直接地图归档、基础目录或外部 ID 标签没有已绑定知识包时，使用完整证据查看和导出。

改变查询条件或来源后须刷新结果；旧后台任务和旧选择不能覆盖新结果。
Esc 关闭、Ctrl+F 内搜、Ctrl+A 及其大写键变体继续可用。

## 文本存档的编码选择

“存档工作台”增加“文本编码”选择，修改后重新读取，重开窗口会恢复选择。
支持自动、UTF-8、GB18030、UTF-16 LE 和 UTF-16 BE。
自动模式识别带 BOM 的 UTF-16；无 BOM 的 UTF-16 请按文件的真实编码明确选择 LE 或 BE。

选择编码后执行严格解码和完整字节回验。BOM 冲突、奇数字节、非法代理项及无法确认的
文本均显示诊断，原始字节保留。已有 GameCache 或二进制存档容器继续按其结构解析。
读取与导出不修改源存档。

```powershell
& '.\GameXRay 游戏档案透视器.exe' savecodes 'D:\存档\角色.txt' --text-encoding utf-16-le --json
& '.\GameXRay 游戏档案透视器.exe' save --save 'D:\存档\角色.txt' --text-encoding utf-16-le --output 'D:\报告\角色.json' --format json
```

`--encoding` 是 `--text-encoding` 的别名。`savecodes --json` 包含成功和失败来源的
完整原文、原始字节、SHA256 与编码诊断。目录、单文件和明确请求的标准输入沿用相同边界。

## 版本识别与只读实时探针

实时读取从合法 PE 资源中的固定版本信息识别版本，不再从任意文件片段猜版本号。
磁盘映像读取验证稳定性，并与当前进程内模块头核对；架构来自实际 PE Machine。
只有 EXE 而没有 `Game.dll` 的客户端能保留其真实映像及架构证据，未验证的布局仍明确报告未知。

模块枚举在系统报告列表增长时扩充缓冲区继续读取。读取失败或进程身份变化保留诊断，
不会把不完整列表当作完整观察。句柄枚举核对表项、世代、存活字段及对象自身句柄，
无法读取或不一致的对象不进入确认存活列表，其余合法对象继续枚举。

档案字节校验遇到空读、短读会失败。完整读出的字节差异在 PE 元数据匹配时仍保留已有
运行时补丁兼容解释，但 PE 元数据匹配不等于完整文件内容相同。
这些改进不表示新增了所有 Reforged 版本的运行时偏移支持；实际支持状态以当次探针诊断为准。

## 离线字段目录与生成输入

字段目录补充了有版本及来源记录的元数据，既有人工修正标签继续保留。
参考元数据用于解释字段含义，不等于当前地图或运行中单位的数值。
完整版本数据作为离线生成输入保存在源码中，运行时查询不依赖网络或训练器目录。

默认生成过程保留已有值并补充参考记录；显式提供元数据目录时，必须通过完整性与歧义检查，
才可重建对应的适用性和范围信息。省略 `common.j` 保留已有常量；明确提供时校验后更新。
缺失、空输入、冲突或生成失败均不会覆盖已有输出。

## 验收与证据

本版的实现依据见 [Trainer 源码审计与实施对照](analysis/war3-trainer-source-adoption-2026-10-29.md)。
静态审计覆盖提供的源码、前端、原生桥、档案、压缩数据和生成链；
源码中存在某项操作不等于其按钮可达或可在当前游戏版本运行。

Windows 全套回归不将失败、跳过或预期失败改写成通过；测试缓存与 pytest 临时根独立于用户资产。
目录版和单文件版分别运行公开入口及实际 GUI 验收。
交付目录的验收结果绑定源码提交、输入清单和发行产物 SHA256，可与程序版本一起核对。
真实 CASC 安装及历史地图批次属于另行明确选择的原始输入验收，不以合成样本替代。
