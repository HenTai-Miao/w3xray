# GameXRay 0.12.0 使用说明

Windows x64 目录版解压后，运行 `GameXRay 游戏档案透视器.exe`，保留旁边的
`_internal` 文件夹。单文件版也提供相同功能。地图、战役、知识包、装备方案、存档和
参考资料的解析与查询都可离线使用，无需安装 Python 或运行 Trainer。

当前源码已按内容解析用途收拢入口：移除了改键方案、插件按键/显示配置和独立键盘速查。
地图中实际编码的对象字段仍完整保留；存档、装备内容、脚本、资源及知识包查询继续可用。

## 单位与技能内容联查

在包查询中使用 `units` / `heroes` 按名称或四码查对象，可同时查看其默认技能、可学习技能
及每个关联技能的完整字段。查询词也会匹配关联技能名称和字段内容；地图将英雄记录在
“单位”主类别时使用 `units`。

`skills` 与单位详情会汇总实际编码的逐级冷却、蓝耗、施法距离、作用范围和持续时间，
保留原值、来源、冲突与显式空覆盖。单位还有攻击、护甲、移速、视野的静态摘要。
这些都是地图内容，不能当成局内当前加成、剩余冷却或已学技能等级。

## 完整脚本调用查询

打开地图并生成资料包后，点击「包查询」，选择「脚本调用」。已有本地资料包可以从
「数据工具 → 打开本地资料包查询（离线）」打开。关键词留空会列出全部调用；可以输入
函数名、四码、参数、所在函数或条件文本，也支持 `&&`、`||`、`%` 和括号组合查询。
对象详情中的「查脚本调用」会把明确选中的四码带入查询。

```powershell
& '.\GameXRay 游戏档案透视器.exe' pack-query 'D:\资料包' calls
& '.\GameXRay 游戏档案透视器.exe' pack-query 'D:\资料包' calls 'CreateItem && I001' --json
& '.\GameXRay 游戏档案透视器.exe' pack-query 'D:\资料包' calls --limit 20
& '.\GameXRay 游戏档案透视器.exe' pack-query 'D:\资料包' again
```

默认不截断结果。显式 `--limit` 选择完整的调用证据记录，保留所选记录的全部参数、
来源与条件，并披露省略数。历史、再次查询、收藏和完整 Markdown 导出沿用包查询入口。
战役逐个查询容器与子地图，诊断与来源归属一并保留。

每条调用包含原始文本、来源、行号、字符偏移、完整参数和所属函数。已证明的标准 API
绑定与源码函数、未知绑定分别显示；动态接收者、局部遮蔽和不明确的运行环境不会猜成
标准 API。条件表示源码中可见的词法上下文，不代表完整执行路径或游戏运行效果。

原始脚本优先提供位置和绑定证据。旧包仅有调用索引时仍可查询全部原始行及扩展字段，
但不会把索引补成源码证明。可读文本经过转换、语言未知、索引冲突、损坏行或来源变化
都有明确诊断。JSON 提供 `calls`、`calls_total`、`calls_omitted`、`call_diagnostics`、
`source_stable`、`script_coverage` 和 `checked_packs`；战役各节也保留相同结构。
查询交付前再次核对全部来源字节与目录成员，变化时保留已捕获证据、返回 2，且不覆盖成功查询记忆。

## 离线装备方案

从「数据工具 → 离线装备方案」打开窗口，选择原始 JSON，点击「读取 / 刷新」。
支持声明为 `schema=1` 的六槽 `codes` 方案，以及九槽 `records/equipment` 方案。
多条方案、重复物品、物品数量、扩展字段及原始 JSON 都完整保留。可按整条方案搜索，
在列表选中一条查看详情，使用内搜和段落定位查找长文本。

```powershell
& '.\GameXRay 游戏档案透视器.exe' loadout 'D:\方案\装备.json' --json
& '.\GameXRay 游戏档案透视器.exe' loadout 'D:\方案\装备.json' --query 'I001 && 主力'
& '.\GameXRay 游戏档案透视器.exe' loadout 'D:\方案\装备.json' --export 'D:\报告\装备.tsv' --format tsv
```

窗口与 CLI 均可导出 JSON、Markdown、TSV 到新的文件；报告始终保留完整来源字节证据、
SHA-256、字段位置和诊断。搜索只选择完整方案记录，不删除未选记录的原始证据。
可以显式选择文本编码；有 BOM 的 UTF-16LE/BE 也可读取。重复关键字段、非法槽位、
超出结构声明的额外槽位和不完整输入都会完整显示，不采用最后一个重复键冒充确认值。
部分输入返回 2 并保留可确认内容，确认的空 `records` 数组则是合法零记录。

这里查看的是文件中声明的装备计划；文件结构匹配不证明它由某个软件生成，也不证明
游戏内实际持有、可装备或物品效果。导出报告不是可回写游戏的方案。读取、筛选和导出
均不连接游戏，不能覆盖原方案、原方案的硬链接或已存在的输出文件。

## 地图与战役解析修复

- 独立地图中的自定义对象基础继承与战役使用同一解析器。父子对象名称、字段、显式空覆盖、
  Skin 层、冲突与来源分别保留，子对象的明确覆盖也会更新父字段证据的覆盖状态。
- 战役 W3F v3 读取完整的雾参数，避免把后续章节误读为空；章节顺序、显示路径和实际可读
  归档路径分别保存，斜杠拼写差异不会直接丢弃已存在的子图。
- 带明确 BOM 的 UTF-16 WTS 可提供地图名称和对象描述。重复声明、非法字符和截断仍保留
  完整原始字节位置与诊断，损坏文本不会冒充已确认翻译。
- 实时档案导入与离线参考目录共用严格 JSON 校验，所有层级的重复键都拒绝，错误原因一致。
- 存档文本中的超长 JSON 数量按原始 token 判断语法，不再因 Python 的整数转换配额中断整份文件或目录扫描，原文和重复字段继续保留。

## 标准资源名称恢复

「导出全部」新增 1,191 条带版本来源的标准 MPQ 路径候选。每个候选仍须命中当前归档的
实际哈希探测链，并成功读取对应成员，才作为确认名称导出。目录存在不代表当前地图包含
该资源，也不代表支持某个游戏版本的运行时解密。

`RecoveredNames/manifest.tsv` 保留每个成员的块、locale/platform、输出路径与哈希；
目录提供的候选追加 `hint_catalog` 来源。`RecoveredNames/name-hint-catalog.json`
记录目录版本、候选数和生成来源哈希，同名输出会使用新名称。没有匹配的候选不会生成
伪造资源，尚不能命名或解密的原块继续保留。既有资源导出的详细操作见
[0.11.0 使用说明](usable-release-0.11.0.md)。

## 来源审查与验收范围

本轮输入为固定提交的 Trainer 源码，344 个受控文件都有身份、审查证据与采用结论，见
[完整源码采用报告](analysis/trainer-source-adoption-2026-10-29-v12.md)和
[逐文件覆盖清单](analysis/trainer-source-coverage-2026-10-29-v12.json)。
运行桥、内存写入、地图注入和外部二进制不作为离线工具功能引入；已有基础目录中的
代码与名称不重复计作新增功能。缺失生成器、外部构建输入和未证明的原生能力均单列边界。

本版的测试、实际 GUI、公开命令与两种 Windows 发行包分别验证，并在最终交付报告中
记录对应源码和文件哈希。没有请求的真实游戏、Reforged CASC 或历史输入验收不计作通过。
本轮使用私有测试缓存；旧发行目录和用户地图、配置、收藏保留。缓存修订号换代使新的
地图解析重新生成结果，不删除原有用户资产。
