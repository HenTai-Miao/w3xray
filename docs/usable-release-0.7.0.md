# GameXRay 0.7.0 只读工作台

本版将实时选中集合、字段证据、地图查询、离线报告比较和字段/版本目录串在同一工作流中。
地图、游戏、存档和参考数据都保留来源与读取状态。源文件只读，不装载外部修改器或调用游戏代码。

## 开始使用

Windows 目录版完整解压后运行 `GameXRay 游戏档案透视器.exe`，保留同目录的 `_internal`。
先打开 `.w3x`、`.w3m` 或 `.w3n`。资料包查询、地图对象、场景、任务、商店、配方、攻略与导出的
已有流程见 [0.6.2 使用说明](usable-release-0.6.2.md)；历史版本的验收记录仍归历史版本。

## 离线使用

地图/战役解析、资料包查询、参考目录、报告比较和存档静态分析均只需本地文件，
无需联网、运行游戏或安装魔兽客户端。打开本地地图后可正常浏览对象、场景、任务、
商店、配方、获取关系和攻略；已导出的资料包也可直接通过 `pack-query` 查询。
没有打开原地图时，可从「数据工具 → 打开本地资料包查询（离线）」选择已有资料包。
「数据工具 → 字段 / 对象 / 版本目录」与「打开 / 比较实时报告（离线）」在没有地图时也可使用。
本地 Classic MPQ 或 CASC 数据作为可选补充；没有对应数据时保留已确认内容及完整来源诊断。

```powershell
& '.\GameXRay 游戏档案透视器.exe' cli 'D:\Maps\地图.w3x' --pack 'D:\报告\新的资料包'
& '.\GameXRay 游戏档案透视器.exe' pack-query 'D:\报告\新的资料包' stats --json
& '.\GameXRay 游戏档案透视器.exe' reference --kind versions --json
```

## 运行中游戏

进入游戏后打开顶栏「live 探针」，发起一次新的读取。完整选中列表保留同码不同实例，
选择一个实例查看它自己的坐标、归属、背包和字段证据。选择物品或单位可直接转到对应类别查询，
也可把该实例的坐标带到 `near`，继续用 `where` / `drop` 查获取线索。
查询始终绑定发起时的地图，切图后不会用旧实例替当前地图作解释。
若探针提示游戏的权限高于工具，请以管理员身份重新运行本工具后再探测。

字段证据显示类型、实际值、读取地址、来源和状态。零是有效数值；未知、不可读、冲突与布局未确认分别显示。
当前已证明的字段与用户声明的新布局分开标注。HP、MP、物品数量及 Reforged 布局没有对应版本证据时保持未知，
静态对象字段、目录里的字段名称或旧修改器的兼容文案不会被提升为实时读数。
同一次报告来自顺序快照读取，不宣称冻结了游戏或获得原子状态。

空选中、空背包与读取失败分别处理。确认的空背包不会套入另一个带物单位的背包。
1.27.0.52240 的完整本地多选按已核对的原生集合读取，同时验证数量、前后链接和终止标记。
主选中单位独立保留，不改变集合顺序；循环、失效、数量冲突或缺失节点保留可确认条目与完整诊断。
其他档案没有独立证明的集合布局时，只展示已确认的主选中证据，并明确标为未确认完整。

## 保存、打开和比较报告

探针窗口可以显式保存当前结构化报告、打开既有报告和比较前后报告。
无需游戏时从「数据工具 → 打开 / 比较实时报告（离线）」进入；该入口不自动发起探针。
打开或比较离线报告不启动游戏读取。
离线报告没有绑定地图时，首次对象/坐标查询会选择本地资料包；随后查询继续使用所选包，
主窗口切换地图不会替换该报告的查询来源。
文件目标使用新名称；已有文件保留，重复保存时选择另一文件名。

```powershell
& '.\GameXRay 游戏档案透视器.exe' live 'D:\Maps\地图.w3x' --report 'D:\报告\第一次.json'
& '.\GameXRay 游戏档案透视器.exe' live 'D:\Maps\地图.w3x' --report 'D:\报告\第二次.json'
& '.\GameXRay 游戏档案透视器.exe' live-report inspect 'D:\报告\第一次.json' --json
& '.\GameXRay 游戏档案透视器.exe' live-report diff 'D:\报告\第一次.json' 'D:\报告\第二次.json' --json
```

比较按实例地址、槽位与来源身份保留观察，不按名字或对象码合并不同单位。
进程出生时间、对局身份或集合完整性不足时，报告说明比较的不确定范围；
不会仅凭一个 PID 或文件路径宣称单位新增、删除或重新出现。已知字段的变化仍可查看。
JSON 保留结构、数字与额外证据，不将未记录字段转为零。

## 字段、对象与版本参考

从「数据工具 → 字段 / 对象 / 版本目录」打开离线目录，或从探针进入参考目录。
没有打开地图时仍能查看本项目已有基础资料和版本档案；指定知识包后加入该图的真实字段证据。
地图自定义定义优先，类别和大小写不同的四码保持不同身份。目录存在不代表当前地图加载或可获得该对象。

```powershell
& '.\GameXRay 游戏档案透视器.exe' reference --kind versions --json
& '.\GameXRay 游戏档案透视器.exe' reference --kind versions --profile-json 'D:\档案\自定义档案.json' --json
& '.\GameXRay 游戏档案透视器.exe' reference --pack 'D:\报告\地图包' --kind fields --category item
& '.\GameXRay 游戏档案透视器.exe' reference '攻击 && 火焰' --pack 'D:\报告\地图包' --json
```

空关键词列完整目录。筛选保留字段边界、别名、类型与来源；显式 `--limit N` 按完整记录限量并披露余量，
`0` / `all` / `全部` 表示全量。没有游戏 build 证据的数据明确标为未记录，不自动套到指定版本。
版本档案分别展示 exact、RVA 表、模板与 Reforged pending；档案文字与本次实机验证分开。

档案的偏移、地址、指针宽度、版本、PE 指纹和 checks 按各自编码域严格检查。
可选字段布局只允许纯数据的固定偏移和指针路径，不接受 Python、DLL 或外部执行提供器。
读取新字段时保留布局来源、原字节、每次指针读取的位置及未确认状态。

## 地图与存档分析

JASS 诊断依据真实源码、语言、声明次序和绑定报告可确认的直接前向调用/引用。
Lua 和未知语言保留自己的语义，不套用 JASS 声明规则。字符串和注释不会成为伪调用。
根目录的 `脚本前向引用.tsv` 保留完整诊断记录，可以用 `pack-query <包> text <函数名>` 查询。
`资源/隐式资源候选.tsv` 区分来源声明、实读确认与不完整表达式；只有完整路径被当前归档实读确认后才补导出资源本体。
资源路径按真实字面值与当前归档验证，长路径和 Unicode 路径不以经验长度跳过，
读取失败与未确认候选保留来源，不因未恢复出路径就宣称资源不存在。

存档分析保留容器、嵌入缓存、记录类别、字段与原始字节偏移。
已知格式按真实编码的数量/长度读取；未知布局、歧义和截断保留确认记录、原字节与尾部诊断。
Preload、Tooltip 等文本载体保留完整静态字符串、语言、编码和来源位置。
存档码候选、脚本声明与真实存档值分别标注，不执行地图代码或解密平台算法。

```powershell
& '.\GameXRay 游戏档案透视器.exe' save --help
& '.\GameXRay 游戏档案透视器.exe' savecodes --help
```

## 维护与验收

源码可用 `uv run python -m gametool`，Windows 维护会话可用 `uv run --no-sync python -X utf8 -m gametool`。
每个命令接受 `--help`。运行时缓存、查询历史、收藏与 GUI 配置在测试时使用独立临时根，
不把测试输出写回用户资产。维护者运行 `gamexray-test`、`gamexray-quality` 和新 EXE 的 `acceptance`。
具体测试数量、原生依赖、GUI、实机/平台跳过项与产物 SHA 以本次发行的独立验收报告为准。
